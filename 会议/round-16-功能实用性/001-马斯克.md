# 001-马斯克：novel-forge 功能实用性第一性原理裁决

## ① 核心诊断

回到第一性原理：**novel-forge 只有一个目标——让本地作者高效写出连贯、长线、不崩坏的小说。** 单用户、无鉴权、本地跑，这意味着「防滥用」「多租户隔离」「服务端保护」这套 SaaS 脚手架在这里全是伪需求。我拿到手的 11 项功能里，真正在核心路径上的只有少数几项，其余要么是把简单事情包了一层糖衣（冗余），要么是给单机工具套上了云服务的思想钢印（错位），最糟的是一个根本不属于这个产品品类的炫技支线。

我的判读是：**写章、精修、章节摘要、自动填表、导入、导出、删节点** 这七项是作者绕不开的刚需，砍掉任何一项都会逼用户去更差的手工绕路；**续写、限流、伏笔检测** 三项有用但属于「薄包装或错位包装」，值得收敛而非保留原状；**游戏开局** 是唯一一个我会直接丢进砍除清单的——它把小说创作平台偷偷改造成了互动游戏引擎，是典型的画蛇添足。

## ② 提升框架

判断一个功能该不该留，只用三条铁律过筛：

1. **不存在时，作者是否被迫绕路？** 被迫 → 留；不被迫 → 疑。
2. **它服务的是「写」还是「看/玩」？** 服务型写作链路（生成、编辑、记忆、一致性、进出）才进核心；分析型、表演型都是可剥枝。
3. **它维护的认知成本是否大于它省下的用户成本？** 单机工具里所有「防别人」的设计，先默认是过度工程，除非能证明防的是上游真实约束。

按此框架，限流之所以「待优化」而非「傻子」，是因为它防的其实是上游 LLM 配额而非本地滥用——前提变了，价值就变了，但实现理由必须重写。伏笔检测同理，它服务质量而非写作，批处理重算的复杂度配不上它的边际收益。

## ③ 具体可落地步骤

- **写章 / 精修 / 章节摘要 / 自动填表 / 导入 / 导出 / 删节点**：保持实装，仅做健壮性复检（T1、T2 已修，需复跑确认）。
- **续写**：不要单独成路由，收敛为「写章 + 自动建下一节点」的组合调用，删掉独立 SSE 链路，省一份维护面。
- **限流**：保留但改叙事——注释与文档写明「这是上游 API 配额保护，不是服务端防滥用」；单机场景可把窗口放宽或做成可关的配置项，别让它挡住作者正常节奏。
- **伏笔检测**：从「常驻幂等重算」改为「按需触发 + 轻量缓存」，去掉后台重算开销，只在用户主动点检时跑。
- **游戏开局**：进砍除清单。叙事+选项分支是另一个产品（互动小说引擎），它的交互模型、状态机、分支存储会持续污染核心写作数据模型，越早切掉越好。

## ④ 风险提示

砍游戏开局最大的反弹会来自「功能丰富度」叙事，但它对核心数据模型的污染是隐性复利债。限流若误判为纯冗余而删除，作者猛灌长文时可能真把上游 API 打挂——所以留，但改理由。续写若舍不得删而维持独立实现，它会和写章在 token 预算、SSE 兜底逻辑上长期两分，埋下第二个 T2 类 bug。伏笔检测常驻重算在 30 万字规模下会悄悄吃资源，收敛为按需是防炸的性价比动作。

## ⑤ 与其他职能的张力（埋伏笔）

- 与「产品视角」的张力：对方可能想用游戏开局讲增长故事，我这边只认「它是否让作者更快写出不崩坏的小说」这一个 KPI，冲突点留给 Chair 拍板。
- 与「美学/体验视角」的张力：续写和限流被我判「待优化」是因为工程冗余，但体验派可能觉得续写一键续章的爽感本身有价值——这是「糖衣是否算价值」的分歧。
- 与「质量/编辑视角」的张力：伏笔检测若被质量派视为核心卖点，我的「收敛为按需」会与之冲突，需讨论「常驻精度」和「按需够用」的取舍。

## ⑥ 11 项功能逐条裁决（马斯克第一性原理）

1. **写章 write**：有意义。这是产品的存在理由，没有它整个工具归零，SSE 流式只是必要的实时反馈而非过度设计。
2. **续写 continue**：待优化。本质是「写章+自动建节点」的薄糖衣，独立成路由只增加维护面，应坍缩为组合调用。
3. **精修 refine**：有意义。没有它作者只能把正文导出改完再粘回，是被逼的绕路，且已修的 token 预算 bug 证明它值得认真做。
4. **章节摘要 summarize**：有意义。它是「长线不崩坏」的中期记忆锚点，30 万字规模下没有摘要上下文必然溢出崩坏，属核心刚需。
5. **限流 rate-limit**：待优化。单机无滥用者，它防的其实是上游 LLM 配额而非服务端，价值真实但理由被写错，应改为可关的配额保护。
6. **自动填表 babylore**：有意义。把正文自动蒸馏进世界卡，是「不崩坏」的自动化一致性引擎，省掉手工维护设定集的漂移。
7. **伏笔检测 foreshadowing**：待优化。服务质量而非写作本身，常驻幂等重算的复杂度配不上边际收益，应改为按需轻量触发。
8. **游戏开局 game/start**：傻子功能。把小说平台偷换成互动游戏引擎，偏离「写连贯小说」核心，持续污染数据模型，直接砍。
9. **导出 export**：有意义。小说困在数据库里毫无意义，导出是作者拿去发布阅读的出口；五格式略有镀金但各格式成本极低，无害。
10. **导入 import**：有意义。作者必然有外部草稿，没有导入就被迫重敲；幂等锁与逐章校验是防重复污染的必要健壮，非过度工程。
11. **删节点 delete**：有意义。基础 CRUD，没有它孤儿章节永久堆积，实现简单且不可缺。
