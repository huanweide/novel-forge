# novel-forge v2.0 长征收口 · 费曼报告

> 写给零基础读者的「真懂检测」版。每一个黑话第一次出现都用大白话讲清它怎么运作，再配一个生活化类比。读完你应该能照着复现，而不只是记住名词。

## 一句话结论

v2.0 把上一轮（v1.9）堆出来的功能做了一次「收口」：删掉一个会卡死界面的批量生成入口、把分散的质量检查聚成一条总分条、把内容安全做成「你能自己加黑名单」、把重复的内存展示合并成一处、并在写作界面被动显示「这本书现在写到第几阶段了」。全部改动通过类型检查 + 468 条自动化测试，并直接对数据库做了「自定义黑名单」读写往返验证。

## 一、干了什么（按四要素展开）

### 1. 质量总分聚合条（P0-2）
**做了什么**：写作界面（PostGenPanel）顶部新增一条「质量总分」，把正文质检、一致性、内容安全、叙事节奏等零散检查汇总成一个分数 + 几个状态灯，作者一眼看懂当前章节健康度。
**为什么**：之前这些检查散落在不同 Tab，作者要挨个点开才知道哪里有问题。聚合条像「体检报告首页」，把分项浓缩成总分。
**方法/效果**：复用已有的纯函数质检逻辑（不新增数据库字段、不加依赖），纯展示增强。零风险、零成本。
**取舍**：没有新建「评分算法」，只是把已有结果「摆到一起」——避免为了酷而引入不可控的新逻辑。

### 2. 前台批量生成统一后台异步（P0-1）
**做了什么**：删掉了「在前台界面里一口气串行生成好几章」的按钮，统一改用后台异步任务（GenerationTask + 轮询）。
**为什么**：前台串行生成是「阻塞式长任务」——生成时界面假死、容易超时断流。后台任务像「点外卖后去干别的，好了通知你」，界面不卡。
**取舍**：这是上一轮已收口的项，本轮只是确认它稳，不再回退到前台串行。

### 3. 角色对话会话落库（P0-3）
**做了什么**：角色聊天/附身的历史会话正式存进数据库（ChatSession），刷新或切换章节后历史不丢，且按「项目 + 角色」隔离。
**为什么**：之前会话只存在内存，一刷新就没。落库像「聊天记录存云端」，换设备/刷新都在。

### 4. 内容安全规则库用户可配置（P2-1，本轮重点）
**做了什么**：内容安全扫描从「写死一套规则」升级为「内置默认规则（你看得到但不能删）+ 你能自己加的黑名单」。你加的词会在扫描时自动叠加，命中了会标记「你的黑名单」。
**为什么**：不同题材有不同敏感词（比如武侠里「剑法」不是暴力，但某些词你想拦），硬编码满足不了所有人。
**方法/效果**：
- 数据库 Project 表新增一个 `customSafetyRules` 字段（JSON 格式，像抽屉里塞一张张小纸条）；
- 扫描函数 `analyzeContentSafety` 支持叠加你的规则；
- 界面 SafetyTab 能增删你的黑名单，保存即落库；
- 你的关键词按「字面文本」匹配（不是正则），并转义特殊字符，防止有人输入 `.*` 之类把扫描搞崩——这一步叫「防正则注入」，类比：不让别人在你家门锁里塞万能钥匙。
**取舍**：默认基线「不可删」而非「可改」，因为基线是所有人的安全底线，允许用户删=允许自己把底线删了；用户只能「增量叠加」。

### 5. 记忆透出合并单组件（P1-3）
**做了什么**：右栏「上下文监控」里合并了原本独立悬浮的「宝宝流记忆召回」面板，生成时自动展开、平时收起，一处看完所有上下文与记忆注入。
**为什么**：两处重复渲染同一类信息，既乱又费性能。合并像「把两份重复的备忘录贴成一张」。

### 6. 右栏实体三子 Tab 同源标注（P1-2）
**做了什么**：实体追踪 / 未收尾线索 / 一致性基线三个子页顶部统一标注「它们都来自同一张结构化表格（角色卡 + 世界书）」，并说明关系图的数据源独立、不强同步。
**为什么**：避免作者以为这三个视图是三套独立数据而困惑。

### 7. 轻量章纲降级为「快速预览」（P1-1）
**做了什么**：原「轻量章纲」按钮改名为「快速预览」，明确它是「写作前快速看一眼草稿大纲、不绑定角色、可随时重生成」，正式大纲请用「抽卡分镜」。
**为什么**：原名容易让人误以为它是正式大纲，导致正式大纲功能被绕过。改名是「说清楚它能干嘛、不能干嘛」。

### 8. 文风两入口关系标注（P1-4）
**做了什么**：写作页「文风」页签（第四部分·文风设定）与顶栏文风模板（第五部分·最高优先级）互相标注层级：模板里的 stylePrompt 始终覆盖同项；叙事视角两个入口打通（本页优先，没填就取文风模板）。
**为什么**：之前两个入口各自为政，作者不知道谁生效。标注后「谁压谁」一目了然。

### 9. 被动展示叙事阶段名（P2-2）
**做了什么**：写作页章节标题区被动显示「全书节奏阶段名（开篇/早期发展/中期发展/后期发展/高潮/收尾）+ 进度%」，基于「当前章在全书的进度位置」自动推导。
**为什么**：长篇小说容易「写几十章后提前剧透终局 / 过早决战 / 结尾又开新线」，阶段提示帮作者对齐长线节奏。
**方法/效果**：直接复用已有的 `computeNarrativeStage` 纯函数（零新增数据库字段、零新子系统）。这是「能复用就复用，不另起炉灶」的典型。

### 10. 升版 2.0.0（M2）
**做了什么**：把版本号从 0.1.0（package.json 历史遗留）/ v1.9.0（公告）统一升到 **v2.0.0**，同步更新前端公告 `changelog-data.ts` 与根目录 `CHANGELOG.md`。
**为什么**：v2.0 是里程碑式收口，版本号要对齐真实进度（package.json 一直停在 0.1.0 是历史遗留，和对外版本号脱节）。

## 二、关键术语大白话

- **纯函数**：一个「给定输入永远得到同样输出、不打电话、不查数据库、不改全局状态」的函数。类比：自动售货机——投币（输入）出饮料（输出），不会今天投币出可乐明天出雪碧。用它做质检/阶段推导，可离线、可复现、好测试。
- **Prisma / 数据库客户端**：帮程序用「写代码」的方式操作数据库的翻译官。改了数据库结构（加字段）后必须重新生成这个翻译官（`prisma generate`），否则它看不懂新字段。
- **JSON 字段**：数据库里一个「能塞任意结构化小数据」的格子，像抽屉里塞一张张小纸条（这里用来存用户的黑名单数组）。
- **防正则注入**：用户输的关键词按「纯文本」匹配而非「正则表达式」匹配，并把 `. * +` 等特殊符号转义。类比：不让别人在你家门锁里塞万能钥匙。
- **双门禁**：每次改动后必跑两道自动检查——① TypeScript 类型检查（`tsc`，0 错）② 自动化测试（`vitest`，全绿）。像出厂前「通电测试 + 功能测试」两道关。
