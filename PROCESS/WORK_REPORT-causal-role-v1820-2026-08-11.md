# 工作单元报告：因果链叙事角色标注系统（v1.8.20）

> 费曼式沉淀 —— 写给零基础也能看懂的自己。
> 日期：2026-08-11 ｜ 项目：novel-forge ｜ 版本：v1.8.20

---

## 一、干了什么（一句话）

给故事线「因果链」视图加了**角色标注**：因果链上的每个事件可以标记为
「推进点 / 卡点 / 分支选择点」三类之一，能**点选**、能**存盘**、能**看统计**，
而且这些标签会随大纲一起**喂给 AI**，让写稿时的大模型理解整条剧情的节奏。

---

## 二、为什么这么做（底层原理 + 用户原话）

用户（瑞宝宝）对上一版因果链提了四点明确批评，本质是"看不懂、点不动、理不清、进不去"：

1. 三个标签名词抽象，"完全没有一个解释，完全不理解"；
2. 选择按钮"没有交互态、点不到"；
3. "因 → 果"方向感弱，"看不出时间先后和因果权重"；
4. 汇集流向"看不出关系（前面重还是后面重）"；
5. **最重要的一条**："这些信息必须能写入上下文，被大语言模型理解并进入写作上下文。"

**类比（大白话）**：把一条故事当成一条河。上一版只在河面上浮了几个没人懂含义的浮标，
还点不动。这一版给每段河道贴上"该加速 / 被堵住 / 要分叉"的牌子——不仅人能看懂，
还要把这份"河道说明书"同步交给舵手（AI），让它划船时知道哪段该猛冲、哪段该停、哪段该选路。

| 步骤 | 做了什么 | 类比 | 工具/文件 |

**UI 具体改了什么（对应批评 1-4）：**

- 顶部新增「怎么读这条链？」一段，用大白话解释三类标签含义 → 解决"看不懂"；
- 节点卡片内放三态按钮组（推进点 / 卡点 / 分支选择点），点击即写库，按钮有 hover/active 态 → 解决"点不动"；
- 顶部按角色筛选 + 实时计数，一眼看出哪类多 → 辅助"理不清"；
- 节点之间流向由「因 → 果」改为「先发生 / 后导致」双标签，明确时间先后顺序与因果权重（哪个是因、哪个是果、汇集时汇入哪头更重）→ 解决"方向感弱 / 看不出关系"；
- 空状态文案改为"这条线还没有事件"。

**上下文注入（对应批评 5）：**
`outline-context.ts` 把时间轴方向文案由"时间轴（已规划/已发生）："改为
"方向：先发生 → 后导致"，并给每个节点打上 `[推进点]/[卡点]/[分支选择点]` 标签，
随大纲注入 LLM。写作时 AI 能读到"哪里该推进、哪里卡住、哪里要分支选择"。

## 四、关键取舍（踩坑与修复，反自欺版）

### 取舍 1：角色标注存数据库，而非 localStorage
上一版因果链是用 localStorage 做临时状态。本次改用数据库字段 `role`——治本：
持久化、可进上下文、可跨会话。代价是多了一次 schema 变更 + 迁移，但这是"真后台"该有的样子。

### 取舍 2（重要，诚实标注）：stale 生成文件卡住主 tsc 门禁
本会话发现 `npx tsc --noEmit`（主配置）报 5 个错，全部来自
`.next/dev/types/routes.d.ts`——一个**被高权限平台进程锁住、且为截断残留**的自动生成文件。

- **根因链**：`next-env.d.ts` 第 3 行 `import "./.next/dev/types/routes.d.ts"` →
  该文件被 `**/*.ts` 匹配进编译 → 加上 Next 语言服务插件强制加载 → 截断文件导致语法错误。
- **为什么删不掉**：旧的 3001 dev server（PID 19092）由平台高权限进程树（19120 → 29624 → 19092）托管，
  当前 token 无权终止，文件被锁，无法删除/重建。
- **怎么验证源码无错**：建临时 `tsconfig.gate.json`——排除 `.next` 与 `next-env.d.ts`、去掉 `next` 插件 →
  纯查我改的 8 个源码文件 → **0 错误**。这说明报错 100% 来自环境残留，不是我的代码。
- **诚实结论**：主配置 tsc 因该 stale 文件在本会话**未达 0 错**；但源码经独立类型检查确认无类型错误，
  vitest 逻辑层面 408 全绿。该 stale 文件会在 dev server 正常重启后由 Next 重新生成为完整版本。

> 反自欺闸门：以上"源码 0 错"是用 gate 配置跑出来的，不是主配置；主配置在本会话环境受限。
> 这一点如实写明，不假装主配置已 0 错。

### 取舍 3：`withNarrativeRoles` 纯函数要做防御
key 用 `${selectedId}:${eventId}` 复合键（避免多线切换串味）；入参做 `Array.isArray` 防御；
非法角色值（如 `"hack"`）过滤为 `null`。这些是"真实世界里 API 会被乱填"的防御，不是过度设计。
