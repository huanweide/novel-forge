## 二、现状逐项核实（已读代码实证）

### 1. 保存边界现状（用户问题 1）
- ✅ `CharacterDialog`：显式"保存"按钮（fetch PUT /api/characters/[id]）
- ✅ `LorebookEditDialog`：显式保存
- ✅ `WorldEditor`：显式"创建/保存"
- ✅ 正文编辑器：手动 `mod+s` 保存 + AI 生成时流式落库（`[PARTIAL_DRAFT]` 草稿标记，断点续写用）
- ✅ 作者指令（authorNote）：显式保存
- ✅ globalPrompt 只在**显式保存角色/词条后**才触发 sync 重编译（不会把编辑中半成品编译进上下文）

**结论**：自动保存边界已经正确（文本/正文=自动；定义/要求/设定=显式）。需要做的不是"改"，是**固化规则 + 补两处体验**：
- 正文编辑框加"未保存"提示（有改动未按 mod+s 时显示小圆点），避免用户以为已保存
- 编辑中的章纲/设定关闭弹窗时若未保存，弹"放弃修改？"确认（现在可能直接丢）

### 2. 关键词/元信息显示现状（用户问题 2）
- ❌ **DrawCards.tsx**：章纲卡片用 `font-mono` 等宽 + 14 种彩色前缀标签（C|/L0|/L1|/R|/L|/K|/CF|/M|/EL|/T|…）逐行渲染——用户看到的是"代码"，不是章纲
- ❌ 章纲生成 prompt（draw/route.ts）强制输出 `### 第一部分：章节元信息 C| ... L0| ... L1| ...` 三层机器格式
- ✅ 正文不受影响（write 有【格式铁律】：正文首行禁止写章节标题）

**改法**：
- 章纲生成 prompt 改为**自然语言章纲**：输出「场景」「事件」「人物」「悬念/钩子」「伏笔」「情绪」六个自然语言小节，去掉 `C|` `R|` `K|` 等前缀
- DrawCards 改为**人话卡片**：标题 + 场景/冲突/悬念/伏笔 分区卡片式展示（不用等宽字体、不用彩色代码行）
- "关键词/元信息"（主视角人物、章尾钩子类型等）→ 折叠为卡片底部小标签（显示就好，不在开头）

### 3. 章纲 vs 剧情预设（用户问题 3，最重要）

**现状机制**（已读 plan-chapter.ts / outline-context.ts / write route）：
- **剧情预设**（`plan-chapter.ts`，write 前自动跑）：LLM 基于"活跃剧情线 + 大纲 + 作者指令 + 记忆召回"推演本章 {焦点/推进线/障碍/转折/执行提示}，注入写作指令 + 回写 storylines（`[plan-chapter] 剧情预设回写`）——**它实际是"剧情推进引擎"，永远在写正文前自动工作，不依赖章纲**
- **章纲**（`chapter-outline`/`draw`）：生成"本章内容清单"（场景/事件/人物）——**当前完全不读剧情线/storylines**，属于盲写
- **问题**：①章纲可能与剧情线脱节（章纲说 A 场景，剧情线推 B 线，正文被两股指令拉扯）；②用户困惑"我都用了剧情预设，还要章纲干嘛"

**统一方案（职责划分 + 打通）**：
```
剧情预设（推进引擎）        章纲（内容蓝图）
  ├─ 永远自动跑（write 前）   ├─ 用户可选（一键生成 or 自己写 or 跳过）
  ├─ 管"剧情往哪走"           ├─ 管"本章具体写哪些场景事件"
  └─ 输入：剧情线+摘要+钩子    └─ 输入：★剧情线+剧情预设方向+上章钩子★
                                  （改造点：现在不读，改成读）
```
- **改造 1（打通）**：`chapter-outline`/`draw` 生成时注入：活跃剧情线摘要 + 上一章结尾钩子 + 最近章节摘要 → 章纲自动衔接剧情（不再盲写）
- **改造 2（职责）**：剧情预设保留（无感自动，价值最大）；章纲保留但标注"可选"
- **改造 3（一键生成去留）**：**保留**，因为对"不知道写什么"的用户是必要起点；但改版后它"基于剧情线生成"，且章纲为空时 AI 写作会自动用剧情预设兜底（现状已如此），所以：有章纲→章纲优先；无章纲→剧情预设独立推进。两不打架

### 4. 附：写正文时"剧情预设是否覆盖"的确认
- write 时 `writingInstruction` 注入顺序：作者指令 → 本节大纲 → **剧情预设 planText** → 格式铁律 → 禁用词
- 剧情预设与大纲**并存注入**（不是替代）——计划里保持这个顺序，只补"章纲生成读剧情线"，让两者一致

## 保存边界铁律（固化，后续新功能必须遵守）

1. **正文/草稿**：允许自动保存（AI 生成流式落库 [PARTIAL_DRAFT]、手动 mod+s）——文本内容丢失成本高
2. **定义/要求类**（角色卡/词条/预设/作者指令/章纲）：**一律显式保存**——用户点"保存/确认"才落库，编辑中的半成品绝不自动持久化
3. **记忆编译**：globalPrompt（上下文预编译）只在**显式保存后**由 sync-global-prompt 触发重编译，编辑中的内容绝不进上下文
4. **UI 承诺**：任何"关窗即丢"的编辑场景必须给未保存提示（confirm/状态标记），禁止静默丢弃

## 四、验收标准（用户视角）

1. 打开抽卡：看到的是**能读的章纲卡**（场景/冲突/悬念/伏笔分区），不是彩色代码
2. 一键生成章纲：生成的章纲**接着上一章钩子、顺着剧情线走**，不与剧情预设打架
3. 写设定/写预设：敲字不自动保存，点保存才生效，关窗未保存会提醒
4. 正文：首行永远干净（无章节标题/无关键词），关键词/元信息在卡片/面板里展示
