# 02 自动化填表与剧情预设流程 —— 运行逻辑 + 踩坑注意事项

## 一、目标
固化「自动化填表 + 生成前剧情预设」的运行逻辑，并把我踩过的坑与排查手法记下来，
供后续对话自查（注意事项是写给我自己的，不是给用户看的）。

## 二、执行流程（运行逻辑）
1. 用户点「生成一章」→ POST /api/generate/write
2. 路由先调 plan-chapter（生成前剧情预设）：读活跃剧情线 + 章纲 + 文风卡 + 召回块 →
   LLM 规划本章推进 → 回写 storyline.chapterBindings → 打印 [plan-chapter]
3. 路由调 orchestrator 写正文：systemPrompt(文风权威) + 召回块 + 角色/世界书 + 章纲
4. 写完后 safeFillAfterWriting：按 fillFrequency / skipLatestChapter 判定是否本章程填表
5. 若本章程填表：无 LoreTable 则自动建「章节事实表」→ babyloreFill(DeepSeek JSON 行操作) →
   回填 LoreTable → 打印 [babylore]
6. recall 模块持续把 LoreTable 注入后续章节上下文 → 打印 [recall]

## 三、关联项
- plan-chapter.ts ↔ storyline.chapterBindings（回写关联，外键 storylineId）
- safeFillAfterWriting ↔ Project 配置字段（频率/跳过）↔ LoreTable（填表落点）
- babyloreFill ↔ recall（回填后注入）↔ [ACU-项目ID] 隔离标记
- orchestrator ↔ globalPrompt（文风卡）↔ genre（条件化系统角色）

## 四、注意事项（写给自己，排查用）—— 已修复项标注版本
1. **文风失效（已修 v0.34.0）**：presets/[id]/apply 路由创建 StyleCard 后漏调 syncGlobalPrompt，
   导致 globalPrompt 不刷新、文风读不到。修复：所有预设类型 apply 后统一调 syncGlobalPrompt。
   自查：应用文风后查 Project.globalPrompt 长度是否 >0、是否含文风关键词。
2. **硬编码修仙压制（已修 v0.34.0）**：orchestrator 系统提示词曾无条件写「白金级玄幻修仙网文作家」，
   非修仙文风被强制按修仙写。修复：三元条件化，修仙类走原版，其他走通用作家角色（文风卡为权威）。
   自查：换非修仙 genre 生成，确认不再出现修仙术语。
3. **无表静默跳过（已修 v0.35.0）**：fill.ts 在项目无 LoreTable 时返回 ok:false 直接跳过，
   不符「生成一章就自动填表」。修复：safeFillAfterWriting 填表前若无表则自动建默认「章节事实表」。
   自查：新项目不套表格模板直接生成，看是否自动建表并填行。
4. **SSE 解析偏差（测试工具注意，非产品 bug）**：后端 SSE 事件是 `data: {type:"babylore_recall"}`
   **没有 `event:` 行**。E2E 脚本若按 `event:` 字段读会全部落入默认 message。
   自查：解析 SSE 必须读 `data:` 行的 JSON.type 字段，不是 `event:` 字段。
5. **端口占用（环境注意）**：3001 常被 Windows 原生 PID 占用，git bash 的 kill（MSYS PID 空间）杀不到。
   必须用 PowerShell `Stop-Process -Id <原生PID> -Force` 按原生 PID 结束。
   定位：PowerShell `Get-NetTCPConnection -LocalPort 3001 -State Listen`。
6. **tsc 调用**：Bash 跑 tsc 用 `command` 参数传命令，勿误用 `arguments`（曾导致 tsc 未执行）。
7. **填表语义**：不是每章都插新行。语义是「事实已存在则 update、无新事实则跳过」→ 动态修正不矛盾。
   看 [babylore] 日志 ops 可能为 0（无新事实），这是正常的，不是 bug。
