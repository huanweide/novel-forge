## 一、干了什么（一句话说清）

小说工坊里点「AI 生成故事线」原本有两套入口、两套实现：左栏的按钮是"**同步阻塞**"式的（点下去要干等大模型吐结果才能继续），工作台里的按钮是"**真后台异步**"式的（点下去立刻返回一个任务编号，后台慢慢跑，前端定时去问"好了没"）。本次把左栏那套也改成异步那套，两条路并一条，用户点起来体验一致、且关掉页面任务也不丢。

顺带：删掉了角色列表里三处调试用的 `console.log`（开发时打印的垃圾日志，会污染浏览器控制台）。

## 二、为什么这么做（拆到底层原理）

**第一性原理提问**：为什么一个"AI 生成"功能要存在两套实现？答案是历史演进——v1.8.4 先做了同步版，v1.8.6 才升级成异步版，但只升级了工作台那一处，左栏忘了跟着改。两套并存会带来三个真问题：

1. **体验不一致**：左栏点生成要干等（页面卡住感），工作台点生成立刻有进度。
2. **复杂度翻倍**：维护两套逻辑，将来改一处容易漏另一处。
3. **"我以为它在了"陷阱**：v1.8.7 自查时已知这个分叉，但当时没动，等于留了个"技术债待办"。

**正确做法**（马斯克第一性原理）：遇到分叉就收敛。既然异步版已被验证更好（关页面不丢任务、有进度条），就让所有入口都走它，删掉同步分叉。这不是"加功能"，是"减复杂度"——减法往往比加法更难、也更有价值。

## 三、用了什么方法 / 工具，效果如何

**方法**：派一个"马斯克视角"自治子 Agent 后台执行（第一性原理推进 + 自修 + 双门禁）；主 Agent 事后做 **trust-but-verify**（不盲信 Agent 汇报，亲自复跑验证）。

**具体改法（代码级，可复现）**：

1. `src/components/workspace/StorylineWorkbench.tsx`
   - 把原来写死在 `handleGenerate` 里的"轮询定时器"逻辑，抽成一个独立函数 `startPolling(taskId)`（就像把一段反复用的代码单独做成"工具函数"）。
   - 新增一个开关 `initialTaskId`（任务编号）。组件一打开，如果带了这个编号，就自动开始轮询。
   - 保留原来的"关页面只清定时器、服务端任务继续跑"逻辑不动。

2. `src/components/workspace/StorylineList.tsx`
   - 左栏「AI生成」按钮：从原来的"同步等结果"改成"发个创建任务的请求 → 拿到任务编号 → 把这个编号交给工作台"。
   - 工作台拿到编号后自动轮询，跑完了把结果填进"中间编辑态"，用户改一改再点"采用并落库"。

**效果验证（关键，非推测）**：
- 主 Agent 亲自跑 `SAFE_DELETE_DISABLE=1 npx tsc --noEmit` → **0 错误**。
- 主 Agent 亲自跑 `npx vitest run` → **43 文件 / 368 测试全绿**（2.94 秒）。
- Grep 全仓确认：`StorylineList.tsx` 已**完全不再**调用同步生成接口；只剩工作台"落库"那一次调用（必须保留，那是真正写进数据库的一步）。

## 四、关键取舍（为什么这么选）

- **抽函数而非复制**：轮询逻辑抽成 `startPolling`，避免左栏和工作台各写一遍定时器代码——否则将来改轮询间隔要改两处，必漏。
- **不删 `initialSuggestions` prop**：虽然这次不用它传同步结果了，但它是向后兼容的接口，留着不伤身，删了反而可能误伤。
- **不碰数据库 schema**：本次纯前端收敛，零表结构变更、零数据迁移，风险最低。
- **`CharacterList.tsx` 的 `console.log` 真删了**：用 `git diff` 看到 3 行删除、Grep 现已 0 匹配，证实 Agent 没谎报。
- **该删的删、不该删的不硬删**：全仓还有不少 `as any`（类型断言）和 SSE 重复解析代码。Agent 想删 `as any` 但发现会触发 TypeScript 报错（TS2322，因为 Prisma 的 JSON 字段和强类型之间本就有"桥接"需求），于是**诚实保留**并记为后续项——这是对的：盲删会引入编译错误，不如留着并标注清楚。
