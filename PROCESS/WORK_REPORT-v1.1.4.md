# 工作单元报告：v1.1.4 魔王系统 Round-5 收尾

> 费曼式教学报告——写给零基础读者，目标是「拿走术语也能懂、照做能复现」。

## 一、干了什么（一句话）

把用户对照竞品「云笔」做体验体检时指出的四类别扭点，一次性补齐并发布：关系图可拖动、下方确认流程默认收起并补用途说明、左侧大纲状态徽章统一、顶栏设置入口合并为一个枢纽弹窗。最终版本 **v1.1.4**，已通过编译与测试、推送到 GitHub。

## 二、为什么这么做（拆到底层原理）

用户的三条底层诉求是：**功能联动**（已有功能打通、不重复造轮子）、**风格统一**（界面一致）、**功能说明**（看不懂的功能要解释）。逐条拆开：

1. **关系图要和角色卡是一体的**：底层原因是关系数据已经有「真源」——角色卡里的 `relationships` 字段（存在数据库，刷新不丢）。旧关系图是另画一套、还不能拖动，等于两份数据两套界面，迟早不同步。正确做法是让关系图直接读角色卡这个真源，改角色卡关系图就自动变。
2. **确认流程别挡正文**：旧确认栏常驻在正文下方，一堆操作按钮挤占阅读空间。它本不该一直占屏幕，应该默认收起成一条极简状态条，想看再展开。
3. **用户看不懂按钮干嘛**：确认流程里「AI诊断」「人工接管」没说明，用户不知道用途。这是「功能可见性」问题——每个操作该有一句话讲清用途。
4. **设置入口太散**：顶栏三个按钮（项目设定/记忆衰减/项目配置）各开各的弹窗，用户找不到项目设定。应把分散入口归到一个枢纽，再分流到各设置弹窗。

## 三、用了什么方法、效果如何（对比）

方法：Next.js + React 组件改造 + 浏览器本地持久化（localStorage）+ 复用既有设计令牌与 Modal/Switch 组件。

| 改动文件 | 做了什么 | 效果 |
|---|---|---|
| `RelationshipGraph.tsx` 重写 | 节点坐标用 pointer 事件拖动（鼠标/触摸通用），松手写 localStorage；连线显示两人关系字；LLM 分析改按钮触发（不再挂载就跑） | 关系图真能和角色卡联动、可拖动、连线标关系、不挡正文也不烧 token |
| `ChapterConfirmBar.tsx` | 默认 `collapsed=true` 存 localStorage；新增「这是什么？确认流程怎么用」折叠说六块用途；AI诊断/人工接管补 title | 正文区不再被挤，功能有人教 |
| 新建 `status-badge.tsx` | 六态三档颜色共享组件，OutlineTree 与确认栏共用，删掉各自重复状态图标 | 左栏状态显示和确认栏一致 |
| 新建 `ProjectSettingsDialog.tsx` | 顶栏三按钮合一，点开枢纽再跳各设置；内联 autoConfirm/autoDeliver 两开关直接 PATCH 后端 | 设置一处可达 |
| 质量门 | tsc 零错误 + 217 测试全绿 | 基线达成 |

## 四、关键取舍（为什么选 A 不选 B）

- **关系图真源选「角色卡 relationships」而非「运行时 LLM 分析」**：角色卡是用户手填、持久化、可编辑的真源；LLM 分析只是辅助比对（找出卡里有但正文没体现的），不能当真源，否则用户改了卡图不变。所以 LLM 改成按需按钮。
- **确认栏默认收起而非删除**：功能不能丢，只是默认不占空间，用户展开仍能看全部操作——这是「体验减法」不是「功能减法」。
- **枢纽弹窗不重写三个设置弹窗，只做跳转归口**：三个弹窗各自已稳定带 Modal 外壳，重写风险大；枢纽只负责「入口归一 + 内联两开关」，跳转时先关枢纽再开子弹窗，改动最小最稳。
- **状态徽章抽共享组件而非各写各的**：消除重复代码，以后改状态样式只改一处。
