> 日期：2026-08-10
> 角色：主 Agent（千惠，团队 lead）+ 5 位 lens Agent + 独立复检 Agent
> 一句话：把"故事线工作台"请 5 个挑剔的"体验官"轮流挑刺，合并同类项投票定出 30 条改进清单，照单施工并逐条验收，最后升版 v1.8.10。

## 一、干了什么（一句话说清）

瑞宝宝要求：对故事线工作台启用 **MaxLoop 魔王系统**（多智能体深度体验 → 集体评审 → 迭代修改，直到问题归零），叠加**马斯克第一性原理决策**。本轮跑完了第一整轮闭环——从 5 份体验报告里收敛出 30 项真实改进并全部落地、验证、升版。

最终交付：**v1.8.10**，双门禁（tsc 0 错 + vitest 368/368 全绿）通过，独立复检确认 30/30 项改进在源码层面真实生效。

---

## 二、为什么这么做（拆到底层原理）

**第一性原理**：一个人改自己写的界面，永远看不出自己写的别扭处——"只缘身在此山中"。要发现真实缺陷，必须让**多个立场不同、互不串供**的"外人"分别去用这个界面，再把他们的抱怨合并同类项、投票筛选，才能避免"作者自嗨式优化"（改了一堆自己觉得好、用户无感的东西）。

**马斯克收敛法则**：体验报告天然会"注水"（每个 Agent 都想显得自己发现问题多）。必须按第一性原理砍掉 50% 噪音——只留"低成本、高共识、真痛点"的项，把架构级大改（重构弹窗、补测试、去 N+1 刷新）记到"观察池"下一轮处理，不让补丁叠补丁把代码搞歪。

这两点决定了流程不是"想到啥改啥"，而是**先集体挑刺、再民主定清单、最后专人施工**。

## 三、方法 / 工具与效果

### 3.1 MaxLoop 六阶段（类比：请 5 个挑剔朋友轮番挑刺 + 监理验收）

把"优化"拆成一条流水线，每个阶段只干一件事：

1. **深度体验**：5 个 lens Agent 各带一个"放大镜"并行去用工作台
   - `ui-ux-a11y`：专挑可访问性与对比度（WCAG AA 实测）
   - `frontend-engineering`：专挑代码质量、死码、性能
   - `copy-empty-state`：专挑中文文案、空状态话术
   - `interaction-flow`：专挑交互流程、状态机、竞态
   - `musk-perspective`：专挑"这功能到底该不该存在、有没有更短路径"
   - 共产出 **92 条原始发现**。
2. **集体评审投票**：Chair（我）当裁判，把 92 条去重、合并同类项，按"≥3 票过半或证据充分"门槛筛 → **30 条 IMP-001~030（本轮施工）+ 12 条 D-01~D-12（架构观察池，下轮回环）**。
3. **方案制定**：每条 IMP 写清楚 before→after 草样 + 验证方式（文件:行号）。
4. **代码执行**：派代码 Agent 照单施工 30 项，Chair 亲跑双门禁 + 亲读 git diff 验收。
5. **复检循环**：派**独立复检 Agent**（与施工 Agent 不同视角）逐条读源码核对 30 项是否真落地——这是第二层 QA，防止"施工 Agent 报完成但其实漏了"。
6. **双文档留痕**：阶段二整合报告 + 阶段三方案 + 本费曼报告。

### 3.2 本轮挑出并修掉的真痛点（举 4 个最该让用户感知的）

- **断链丢失（IMP-010，P1）**：原计划关闭故事线弹窗会顺手把"正在后台生成的 AI 任务 id"也清空，导致用户关掉再打开就**再也接不回那个生成任务**，任务在途丢失。修复：关弹窗只卸载界面、保留任务 id；新增 `onTaskSettled` 契约，等任务真正 done/failed 才让父级清理；重开若发现还有未结算任务 id 就自动恢复轮询。配套修了连点锁（防连点建多个游离任务）、轮询空 catch 卡死（网络异常时无限空转）、双重轮询（旧 interval 没清又开新的）。
- **对比度不达标（IMP-002，P1）**：AI 生成按钮原来是"紫罗兰字 + 浅紫底"，对比度仅 3.75:1，弱视用户看不清（标准 ≥4.5:1）。改实心深底 + 浅字 #F0EEE8，远超国标。
- **键盘/读屏不可达（IMP-001，P1）**：左列"标记完结"原来是 `<span onClick>`（鼠标点击的div），键盘 Tab 不到、读屏不读。改标准 `<button>` + `aria-label` + 焦点环。
- **文案暴露 jargon（IMP-020）**："采用并落库 / 落库中 / 落库失败"是开发黑话，用户看不懂。统一为"保存到故事线 / 保存中 / 保存失败"。顺带把线索集标题里写死的"纸集 / 龙王寨 / 尸检报告"等项目专有名词去掉（那是某本书的例子，放到通用工具里很怪），改为"线索集（伏笔、物证、人物备注等）"。

### 3.3 质量门（双门禁，铁律）

- `SAFE_DELETE_DISABLE=1 npx tsc --noEmit` → **0 错误**
- `npx vitest run` → **43 文件 368 测试全绿**

每次改完都重跑，特别是 Chair 亲补 IMP-010 后立刻重跑确认无回归。

- 投票收敛：30 条实施 + 12 条观察池。

## 四、关键取舍（为什么选 A 不选 B）

- **为什么把架构级大改（D-01~D-12：模态弹窗改侧边栏、补测试、去 N+1 全量刷新）压到下一轮？**
  因为马斯克法则要求"删 50% 噪音、最短路径"。这些项收益大但风险高、改动面宽，本轮先吃下"低成本高共识"的 30 项真痛点（文案、对比度、断链、a11y），避免一边修 bug 一边重构把代码搞乱。观察池已明确记录，下一轮照单处理，不丢。
- **为什么 IMP-010 由 Chair 亲补而非交给代码 Agent？**
  代码 Agent 报告 IMP-010 "完成"，但只删了 `setGenTaskId(null)` 却没把任务 id 回传给工作台做重开恢复，也没在任务结算后清理它——留下永不清除的陈旧 id，恢复逻辑根本没接上。Chair 识别这是"半完成"，亲自补完：加 `onTaskSettled` prop + 父级 `initialTaskId={genTaskId ?? undefined}` 回传 + 结算清理。这正说明"独立复检 / 亲验"不是形式主义，而是真能抓出施工遗漏。
- **为什么不一次把 92 条全做？**
  第一性原理：其中大量是"风格偏好"（某 Agent 想统一间距），非用户痛点。投票 + 马斯克收敛把它们砍掉，省下的精力留给真正影响使用的 30 项。
