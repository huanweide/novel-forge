# 工作单元报告：v1.3.0 自动填表全面打通（实测驱动）

> 费曼式教学报告——你让我「自己去测试一下一键追评」，这份报告就是完整实测记录：发现问题 → 挖根因 → 修复 → 复测通过。

## 一、干了什么（一句话）

你说要「确认自动填表的逻辑：角色卡、世界卡内的所有内容都能填写，格式与内置相同，速度不能太慢，自己去测」。我去「新城 · 龙陨之地」实测了一键追评，挖出并修掉一个让填表**4 分 18 秒还失败**的根因，并给自动填表加上了**角色卡/世界书实体自动填充**。修复后一键追评 **7 秒完成、16 条事实全部落地**。

## 二、为什么这么做（拆到底层）

你的两个诉求对应两个底层问题：

1. **速度**：实测一键追评，4m18s 返回「模型未返回任何有效操作」——失败且极慢。挖根因（一步步排除）：
   - 直接调 LLM API：191ms 正常返回合法 JSON → LLM 本身不慢。
   - dev server 里跑：`content` 为空、推理内容 2.3 万字符、`finish_reason=length`。
   - **根因**：配置的模型 `deepseek-v4-flash` 是「推理模型」——它会先长篇推理再给答案。填表 prompt 较大时，推理过程把 `max_tokens=8000` 全吃光，最终答案（content）被截断为空 → 解析出 0 个操作 → 失败重试 → 每次都很慢。
   - 类比：让一个「先打草稿再交卷」的考生做填空题，草稿纸（token 预算）用完了，答案没写上去。
   - **修法**：填表是纯抽取任务，不需要推理——统一改用同厂商的基础对话模型 `deepseek-chat`（实测 154-319ms 直出 JSON，无推理）。这是「对任务选对模型」，不是降级。
2. **角色卡/世界卡内容也能填**：原来填表链路只写结构化表格（LoreTable），从不写角色卡（CharacterCard）和世界书（LorebookEntry）。新增实体同步：每章填表后，让 LLM 按**内置格式**抽取本章新出现的角色与世界观实体，角色建角色卡、其他建世界书词条，查重防重复。

## 三、用了什么方法、效果如何（实测数据）

| 项 | 修复前 | 修复后 |
|---|---|---|
| 一键追评耗时 | 4m18s（失败，ops=0） | **7.16s（成功，applied=16）**，提速约 36 倍 |
| 单章填表 | 失败 | 7.4s 成功，16 条事实全落地 |
| LLM 单次调用 | 推理模型（慢、吞 token、content 空） | deepseek-chat 154-319ms 直出 |
| 表格填充 | 不写 | geo/treasure/faction 三表正确填充（名称零杜撰） |
| 角色卡/世界书 | 不写 | 自动创建（见下） |

**实体同步实测**（「新城 · 龙陨之地」第四章）：
- 角色卡「韩姓男子」自动创建：role=supporting、background 3-5 句基于正文、storyLine、appearance.features、personality、tags 全部就位。
- 世界书词条「欧阳集团」(faction)、「临港新城」(geography) 自动创建：category 映射正确、content 详实。
- 已有 16 张角色卡、19 条世界书词条全部查重跳过（繁简/错别字变体也不会重复建）。

## 四、关键取舍（为什么选 A 不选 B）

- **换模型而不是加大 max_tokens**：试过把 max_tokens 加到 24000——结果响应体生成超长、`res.json()` 挂起 120s 超时。推理模型治标不治本；换非推理模型才是根治（快、稳、直出）。
- **实体同步独立 LLM 调用，而不是塞进填表协议**：改 fill 的 JSON 协议（让模型同时输出表格 operations + 实体）风险高、可能破坏表格稳定性；独立一次轻量调用（每章 ~1s）安全且互不影响。
- **查重复用 `isSimilarName`**：不重复造轮子，复用已有的繁简/错别字去重逻辑，避免「韩姓男子」因写法变体被建两张卡。
- **实体同步失败不影响表格**：`syncChapterEntities(...).catch(() => null)`——实体抽取失败时表格结果照常返回，不会因小失大。

## 可复现步骤（照做即可）

```bash
cd novel-forge
npm run dev   # 3001

# 1. 实测一键追评（用你的项目 id）
curl -X POST http://localhost:3001/api/babylore/fill-all \
  -H "Content-Type: application/json" \
  -d '{"projectId":"<项目id>"}'

# 2. 查看填表结果：结构化表格 rows、CharacterCard、LorebookEntry 是否新增
# 3. 质量门
SAFE_DELETE_DISABLE=1 node node_modules/typescript/bin/tsc --noEmit
node node_modules/vitest/vitest.mjs run
```
