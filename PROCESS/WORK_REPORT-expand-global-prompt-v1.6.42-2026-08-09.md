## 一句话总结

小说创作工具里有条「全局写作说明书」（globalPrompt），本该由唯一的同步引擎（syncGlobalPrompt）统一生成。但「批量展开角色」这个接口里藏了一段用错标记的旧代码，导致每次展开角色都会用一份**残缺版说明书**把正版覆盖掉——等于刚立好的规矩被架空。本轮把这处漏洞堵死，让「正版唯一、残缺版永不落库」真正生效。版本从 v1.6.41 升到 v1.6.42。

## 四要素展开

### ① 干了什么

修改了一个文件 `src/app/api/characters/expand/route.ts`（角色批量扩展接口），删掉其中一段「用残缺版覆盖正版全局提示词」的逻辑，改成：已有正版就直接复用，没有才去让同步引擎重建，连同步引擎都造不出（项目真没数据）才临时用残缺版兜底且**绝不写进数据库**。同步推送了双 changelog 升版到 v1.6.42。

### ② 为什么这么做（第一性原理）

先说背景里的几个「大白话概念」：

- **globalPrompt（全局提示词）**：可以类比成「给 AI 代笔的《写作总纲说明书》」。里面写着：这是本什么书、有哪些角色、世界规则是什么、文风怎么把握。AI 每写一章都要先读它，才知道怎么写才不跑偏。
- **syncGlobalPrompt（同步引擎）**：类比成「专职秘书」。每当作者增删改了角色卡/世界书/文风卡，秘书就重新编一份最新最全的《说明书》存好。它是**唯一**被允许编写这份说明书的人。
- **单一真相源（Single Source of Truth）**：一个工程原则，类比成「全公司只有一台打印机出正式文件，谁都不许手写复印件替代」。v1.6.40/41 刚定了这条铁律：globalPrompt 只能由 syncGlobalPrompt 写，其他任何地方都不许直写。
- **SSE 流式（Server-Sent Events）**：类比成「直播」。接口不是等全部算完一次性给结果，而是角色一个一个算好就立刻推给前端，像直播逐条弹幕。

**问题根因（第一性原理拆解）**：expand 接口旧代码第 234 行想判断「当前存的说明书是不是最新的」，用的判断标记是 `世界观(${loreCount}条)`（半角括号、还写错成「世界观」）。但秘书（sync）真正写进说明书的格式是 `世界书（共N条）`（全角括号、正确用词「世界书」）。**两套格式永远对不上 → 这个判断永远以为「不是最新的」→ 于是每次都绕过秘书，自己手写一份残缺版说明书（缺角色段落、缺文风、缺叙事视角比例、缺探讨布置）直接覆盖正版**。

这比「偶尔漏同步」严重得多：它不是「某次没同步」，而是**每次展开角色都在破坏正版**。v1.6.40/41 刚立的铁律等于摆设。

**物理现实优先**：残缺版会丢掉角色信息，AI 展开新角色时反而少了上下文，质量更差——这违反「让 AI 拿到最全信息」的物理目标。所以必须修。

### ③ 方法工具与效果

- **检测方法**：用 Bash 的 `grep` 穷举全仓 `syncGlobalPrompt` 的所有调用点（30+ 处）和全部直写 `globalPrompt` 的点交叉比对；再派一个**只读**的子 Agent 扫描确凿 bug。关键突破是自己肉眼比对了 sync 输出格式（`世界书（共N条）`）和 expand 里的判断标记（`世界观(${loreCount}条)`），发现永远不匹配——这是漏洞的真正成因。
- **修复手段**：把那段「判断+直写」逻辑替换为——
  ```
  let context = project.globalPrompt || "";
  if (!context) {                       // 只有真的没有说明书才动手
    const synced = await syncGlobalPrompt(projectId);  // 让秘书重建正版
    if (synced) context = synced;        // 有正版就用正版
    else { /* 项目真没数据，局部用残缺版兜底，但不写库 */ }
  }
  ```
  同时删掉了一个「永不命中」的 `loreCount` 数据库查询（因为它只服务于那个永远为假的判断，纯属浪费）。
- **验证手段（双门禁，零容忍）**：
  - `SAFE_DELETE_DISABLE=1 npx tsc --noEmit --incremental false` → **0 错误**（关增量缓存，防上次的缓存幽灵报错）。
  - `npx vitest run` → **35 文件 323/323 全绿**（本轮是收敛性删除，既有测试全量通过）。
- **效果**：单一真相源真正闭合——expand 接口再也污染不了 globalPrompt；运行期零行为变化，用户对「展开角色」功能无感；删了一段无效 DB 查询，反而省了一次查询。

## 术语大白话自检（命名 ≠ 理解闸门）

- **globalPrompt / 全局提示词**：给 AI 代笔的《写作总纲说明书》，写每章前必读。
- **syncGlobalPrompt / 同步引擎**：专职秘书，角色/世界书/文风一变就重编最新说明书，是唯一能写说明书的人。
- **单一真相源**：全公司只有一台打印机出正式文件，谁都不许手写复印件替代——避免多份互相矛盾。
- **SSE 流式**：像直播，角色算好一个推一个，不等全算完。
- **tsc**：TypeScript 编译器，专职查「代码里类型写得对不对」，0 错误才放行。
- **vitest**：测试框架，自动跑几百个「预期行为」小案例，全绿才放心。
- **`as any`**：TypeScript 里的「我不管类型了，当它是任意类型」——用多了等于没类型保护，是技术债但不是 bug。

去掉上面这些词，读者还能懂吗？能：核心就是「一个接口偷偷用手写残次品覆盖了正版写作说明书，把它堵死，让正版唯一生效」。
