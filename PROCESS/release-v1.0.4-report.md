# Novel Forge · MaxLoop 深度迭代总结报告（v1.0.2 → v1.0.4）

> 费曼式写法：零基础可读，术语先讲大白话再配类比，结论可复现。
> 收口版本：v1.0.4（commit 1a16952，已推送 origin main）

## 一、干了什么（一句话）

对已经「功能全绿」的 novel-forge 写作工具，又跑了两轮「魔王系统」深度审计（round-14 五透镜 + round-15 同源闭环），专门挖功能测试查不出的深层坑——**数据完整性**和**内存泄漏**，共修掉 **3 条 P1（数据类）+ 1 条同源 P2（泄漏）**，让产品从「功能正确」进一步收敛到「数据与资源也稳妥」。

## 二、为什么这么做（第一性原理）

功能测试（211 个单测 + 9 个真机脚本）只能证明「按设计走通了」。但三类问题它覆盖不到：
1. **数据丢失**：备份包没包含某些数据、导入时关系字段契约对不上，跑通了却悄悄丢东西——这叫「静默失败」，比报错更危险。
2. **超时回滚**：导入大书时，数据库事务有默认 5 秒上限，几百章串行写入超过 5 秒就整段作废——小书测不出来，用户真写大长篇才炸。
3. **内存泄漏**：前端缓存只加不删，长期切项目会越占越多（和之前修过的监控缓存是同一类毛病）。

这些不修，用户在某天真实场景里会吃到「备份还原丢设定」「导入一半全没了」「网页越用越卡」。所以要在发布前清零。

## 三、方法工具与效果

**工具**：MaxLoop 魔王系统（多智能体评审—迭代框架）。本轮换了打法——不泛泛体验，而是派 5 个**只读审计智能体**，每人盯一个功能测试顾不上的维度（逻辑/异常/数据一致性/安全/性能），必须带源码行号证据回来。

**关键纪律（Trust but verify）**： chair（负责人）不轻信 Agent 回报，亲自读源码核对。这轮就抓出一个**证据冲突**——一个 Agent 说「两处事务都加了超时」，另一个说「commit 事务缺超时」，查源码后是后者对，前者偏乐观。凡是 Agent 报的「已修复」都靠门禁 + 真机脚本坐实。

**效果数据**：
| 项 | 结果 |
|---|---|
| tsc 类型检查 | 0 错误 |
| 单元测试 | 211 passed（全绿） |
| 真机复验脚本（针对 3 条 P1） | 3/3 PASS |
| 修复条目 | 3 P1 + 1 同源 P2 |
| 升版 | v1.0.3（d38a4bb）+ v1.0.4（1a16952），均已推送 |

## 四、关键取舍（为什么这么修、不修别的）

**修了什么、怎么修的**：
- **IMP-501 备份静默丢数据**：`.nfproject` 备份包本就不含「游戏进度/版本历史/记忆摘要/伏笔追踪/待兑现事项」——这是产品取舍（代码注释写明「匹配计划」），但前端**没告诉用户**，造成「备份=全量」的错觉。修复不是硬塞进备份（那会破坏设计），而是**让备份回执自己声明「我不含这些」**（加 `excluded` 字段）+ 前端 BackupDialog 弹一行说明。类比：搬家打包单上写明「易碎品不在此箱」，而不是把钢琴硬塞进纸箱。
- **IMP-502 markdown 角色关系失效**：从文本导进来的角色，关系字段写成了 `targetCharacterId`（名字塞错位置），系统别的地方都认 `targetName`，结果角色关系在世界书里显示成 `?(?)`。改成统一用 `targetName`——一行改动对齐契约。类比：大家都用「工号」对人对不上，统一改成「姓名」就对上了。
- **IMP-503 大书导入事务超时**：导入落库的事务补了 `{ timeout: 120000 }`（120 秒），和另一个导入接口口径一致，避免默认 5 秒上限把大书整段回滚。
- **IMP-504 前端缓存泄漏**：实体高亮的缓存加了 256 条上限 + 自动删最旧，和之前修的监控缓存同构闭环。

**没修什么、为什么**： round-14 还报了一堆 P2（游戏/填表并发覆盖写、生成时把整本书正文都读进内存、导出锚点同名碰撞、物品数量没校验负数等）。这些**现实里极难触发**（前端是串行点击、单标签页）、或**要重写一大片才修**、或**纯属展示层不影响数据**。硬修反而引入新风险，所以诚实归档到观察池，标注「非阻断、需本地目测」，不构成「项目还有问题」的阻断条件。

## 五、诚实边界（不伪装完成的部分）

- 沙箱无 Chromium（浏览器），**前端 UI 的实际视觉表现**（BackupDialog 文案样式、缓存增长真实占用）只在代码层验证 + 逻辑推断，未做真人浏览器目测。需在本地 `npm run dev` 目测确认。
- 并发类 P2（游戏双标签页同时操作）只在代码层指出缺口，未做真机并发压测（难构造且非高频路径）。
- 所有「已修复」均经 tsc + 211 测试 + 真机脚本三道门禁，非口头宣称。


**结论**：MaxLoop 已达「项目无阻断性问题」收敛态——功能正确性（前数轮清零）+ 数据完整性（本轮）+ 已知泄漏护栏（本轮）全部闭环，门禁全绿。残留项均为非阻断健壮性增强，诚实标注。
