# 03 色子抽卡与剧情线关联 —— 现状、扩展实现与验证

## 一、目标
让「色子（抽卡）剧情预设」的采用结果**持久化关联到剧情线(Storyline)**，写入
Storyline.chapterBindings（标记 element:"preset"），使生成前剧情规划(plan-chapter)能读到
「用户用色子选定的走向」作为剧情预设。对齐用户原话：「色子也算是剧情预设」。

## 二、执行流程
1. **探查现状**（用 Explore agent，已做）：
   - DrawCards.tsx 第274行「采用此路线」→ handleSelect → onSelect 回调 → 父组件 handleDrawSelect
   - handleDrawSelect 只 PUT /api/story/nodes/[id] 写 StoryNode.outline，**完全不碰 Storyline**
   - StoryNode 模型无 storyline 外键；Storyline.chapterBindings 仅由 plan-chapter / apply-updates / 手动编辑三处写入
   - 结论：**色子采用与剧情线彻底脱钩**，缺口=「采用时无 storyline 上下文 + 无回写 storyline 代码」
2. **定方案 A（最小侵入）**：复用已有 PUT /api/storylines/[id]（已支持 chapterBindings 字段），
   不新增端点、不改 Prisma schema。
3. **落地 4 处编辑**：
   - DrawCards.tsx props 加 `storylineId?`，handleSelect 透传 `onSelect(card, storylineId)`
   - page.tsx 渲染 DrawCards 时传 `storylineId={活跃剧情线.id}`（status==="active" || type==="main"）
   - page.tsx handleDrawSelect 签名加 `storylineId?`，写 node 成功后追加 PUT storyline.chapterBindings
     （element:"preset"、chapterId、note 含 cardLabel/coreConflict/mood；同 node 重采用先去重再追加）
4. **验证**：tsc + build 通过；重启 dev；脚本验证 PUT /api/storylines/[id] 能追加 preset 条目且
   GET 回读正确（生成前读取链路已由 v0.33 E2E 证明 plan-chapter 读 storylines）。

## 三、关联项（如何编写关联）
- DrawCards(storylineId prop) → page.tsx(渲染传活跃 storylineId) → handleDrawSelect(storylineId 参数)
- handleDrawSelect → PUT /api/story/nodes/[id]（写章纲）＋ PUT /api/storylines/[id]（追加 chapterBindings）
- Storyline.chapterBindings(preset 条目) ← plan-chapter.ts 生成前读取 → 影响本章剧情规划
- 数据流闭环：抽卡采用 → 剧情线 preset → 生成前规划读到 → 正文按色子走向推进

## 四、注意事项（写给自己）
- chapterBindings 是整段替换（PUT 接受 body.chapterBindings 整体），所以前端要先取现有数组再追加，
  **不能只 PUT 单个条目**，否则覆盖 plan-chapter 已回写的内容。已实现 next = [...existing.filter(去重), entry]。
- 同 node 重采用会堆叠多条 preset → 已用 filter 去重（同 chapterId+element==="preset" 先移除）。
- 若项目无 active storyline，storylineId 为 undefined → 不回写（graceful，不影响采用章纲）。
- preset 条目结构与 apply-updates 写入的一致（{element, chapterId, note}），plan-chapter 读取时兼容。
