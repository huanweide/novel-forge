# 工作单元报告 · Novel Forge v1.6.2（UI 三项体检收尾 + 生成链路健壮性）

> 费曼式沉淀。读者假设为零基础大学生，凡术语第一次出现先用大白话讲清「它怎么运作」，再配一个生活化类比。本文所有改动均已在本地实测并随 v1.6.2 提交推送（commit c863dcc，已 push 到 `huanweide/novel-forge` main）。

---

## 一、干了什么（一句话）

给 Novel Forge 这个「本地小说写作工具」做了一次 UI 全面体检并补了两处生成链路的真实缺陷：① 每个按钮点完都要有成功/失败提示；② 删掉重复的按钮；③ 按钮配色统一成一套设计系统；④ 真实生成章节时，AI 偶尔返回空内容会留下「垃圾空章」或「垃圾标题」，加了重试和回滚兜底。

## 二、为什么这么做（拆到底层原理）

用户给了三条硬性要求，背后是「可用性」和「一致性」两个第一性原理：

- **按钮要有反馈**：人点击按钮后如果界面毫无反应，会以为「没点上」「卡了」。这跟按电梯按钮没亮灯一样让人不安。所以每个确认动作都要给一个明确的轻提示（toast）。
- **按钮不要重复**：页面上出现两个做同一件事的入口（比如工具箱在工具栏有一份、又在「更多▾」里有一份），用户会困惑「点哪个」。冗余入口是之前迭代时没清干净的遗留。
- **配色要统一**：之前有些组件直接写死颜色（比如「爱情关系线」用独立粉红色），跟全站暗色主题不协调，像一件西装搭了只拖鞋。统一收归到一套「设计令牌」（见下方术语）才能整体协调。

生成链路的两处缺陷是**真实跑出来的**，不是凭空猜的：我在「新城」项目真实触发了第 7 章生成，发现 AI 网关偶尔返回空内容，于是暴露了两个真实 bug（见第四节）。

## 三、用了什么方法、效果如何

### 术语先讲清（费曼闸门）

- **Toast（轻提示）**：屏幕角落弹出的一个小条，几秒后自动消失，用来告诉你「成功了」或「出错了」。类比：微波炉「叮」一声告诉你热好了，不用一直盯着。项目里有一套封装好的函数：`toastSuccess()`（成功）、`toastError()`（失败）、`toastInfo()`（普通信息）。
- **设计令牌（Design Token）**：把全站颜色集中定义成一组变量（比如 `--nv-primary` 主色、`--nv-creative` 创意色、`--nv-text-primary` 正文色），组件不直接写死颜色，而是引用变量。类比：家里所有房间共用一个调色盘，想换风格只改调色盘一处，全屋跟着变。
- **SSE（Server-Sent Events，服务端推送事件）**：一种让服务器像「流水」一样一点点把生成进度推给浏览器的技术，用来做写作时的实时进度条。类比：下载文件时进度条一点点涨，而不是等半天突然蹦出结果。
- **状态机里的节点状态**：每章在数据库里有个「状态」字段，比如 `drafting`（写作中）、`completed`（已完成）、`outline_only`（只有大纲没有正文）。类比：外卖订单的「待接单/配送中/已完成」。

## 四、关键取舍（踩坑与修复全过程）

### 坑 1：摘要偶发空返回 → 写了垃圾标题

真实生成时，章节命名依赖 AI 对整章生成的「摘要」当章名。但 LLM 网关在本沙箱偶发返回空字符串，导致命名段拿到空 `summary`，章节标题就留成了「第7章」这种无意义占位。

- **为什么是真实缺陷而非偶发**：不是网关抽风，而是代码对「空返回」没有任何兜底，第一次空就只能留垃圾标题。
- **怎么修**：在 `post-processor.ts` 调用摘要的地方套了「最多重试 3 次」的循环，只有拿到非空 summary 才继续；连败 3 次就老老实实保留空 summary 并**安全跳过命名段**，绝不写垃圾标题。类比：问人一个问题没听清，再问两遍；三遍都没听清就先不记，也不瞎编一个答案。

### 坑 2：正文空响应 → 留下 drafting 脏空章

又一次真实生成，AI 直接没吐正文（网关拒绝/空），但节点已经建好、状态停在 `drafting`，正文是空的——数据库里就多了一章「写作中但没内容」的脏数据。

- **怎么修**：在 `write/route.ts` 检测到正文为空时，先把节点状态回滚成 `outline_only`（同时 content 清空），再做错误处理返回。类比：做菜做到一半发现没食材，不像没做好的菜端上桌，而是把锅撤下、标记「今天只备了料没出菜」。

### 取舍权衡

- **为什么不反复重试赌网关**：health 接口返回的 `llm.ok:true` 只代表「配置能加载」，不代表每次调用都通。沙箱 LLM 网关在本会话极不稳定，与其让用户在界面上干等多次重试，不如用「重试 3 次 + 失败安全回滚」的确定性防御，保证库里永远不出现垃圾数据。
- **为什么把 alert 换成 toast**：原生 `alert` 会阻塞界面（点了才能继续），且样式跟暗色主题格格不入；toast 不阻塞、样式统一。

## 五、照做即可复现的步骤

1. 进入工作副本：`cd novel-forge`
2. 跑类型门禁（零错误才算过）：`SAFE_DELETE_DISABLE=1 npx tsc --noEmit`
3. 跑测试（217 全绿）：`node node_modules/vitest/vitest.mjs run`
4. 验证生成链路：启动 `npm run dev`（端口 3001），在「新城」项目点生成新章，观察 SSE 进度 → 自动确认 → 章名回填 → DONE。
5. 静态自查去重：`grep -rn "onOpenToolbox" src/` 应返回零结果。
