# 工作单元报告：v1.2.0 角色卡体系升级

> 费曼式教学报告——写给零基础读者：拿走术语也能懂、照做能复现。

## 一、干了什么（一句话）

把「角色卡编辑」这一整套升级了一遍：AI 填满现在真的会填满所有属性（新增故事线字段、补上性格三层、时间线和人际关系也填）、关系图搬进角色卡里、自动分类变简单、自动填表从「更多」里拿出来还加了一键追评所有未填表章节。版本 v1.2.0 已通过编译与测试并推送 GitHub。

## 二、为什么这么做（拆到底层）

你提了几类疑问，核心是「**AI 填满到底填不填得全**」和「**这些功能为什么散在各处**」。

拆开看：
1. **AI 填满漏填**：后端只硬编码检查 10 个字段，时间线、人际关系、当前状态这些根本不在检查列表里——等于 AI 根本没被问「要不要填这些」。「性格特征」虽然会填，但它下面还有三层（表层/中层/内核）从来没人填。「故事线」更彻底——角色卡里压根没这个字段。所以先把字段补全（新增 storyLine），再让检测逻辑覆盖所有该填的，前端回填也别再把 AI 结果「保留原值」丢回去。
2. **全选和 AI 扩展不联动**：全选只是勾选，不会自动开跑。让全选后自动触发扩展；扩展和填满的字段范围也对齐，避免两个功能填的东西不一样。
3. **自动分类太复杂**：原来四路并行（称号/学校/经历/俱乐部），是足球同人特化的，对一般小说又慢又碎。改成一路简单分组（3-6 个自然群体，按阵营/身份/定位），够用且不拆碎。
4. **关系图放错地方**：右栏侧栏里有一个关系图，角色卡里的人际关系却只是纯文本。你早就说过「分为列表和网格，网格就是关系图」——把关系图从右栏删掉、内置进角色卡的人际关系区块，列表/关系图切换着看；同时让 AI 填满/扩展能自动检测人物关系，从手填变成 AI 检测。
5. **自动填表藏太深**：藏在「更多」下拉里叫「自动化」。它是常用功能，提成一级按钮，改名叫「自动填表」，并直接放一个「一键追评所有未填表章节」。

## 三、用了什么方法、效果如何（对比）

| 改动 | 做法 | 效果 |
|---|---|---|
| 新增「故事线」 | schema 加字段 + db push + 表单加区块 | 角色卡能写/存/AI 填故事线 |
| AI 填满全覆盖 | 后端检测列表扩到 timeline/relationships/storyLine，性格三层全空也触发；prompt 加简洁约束；前端回填去保留逻辑 | 点一次 AI 填满，所有空属性都补，且内容更精炼 |
| 性格三层合并写回 | 写库改为「保留已有的，补缺的三层」 | 不会把已填的性格覆盖掉 |
| 全选联动 | 全选后自动调 AI 扩展；扩展后端补 storyLine 与三层 | 一次点选即开跑，扩展/填满字段一致 |
| 分类简化 | 四维 → 单路 3-6 组自然分组；面板兼容 | 又快又直观，不再拆碎 |
| 关系图迁移 | 右栏删关系图；角色卡人际关系加「列表/关系图」切换 | 关系图就在角色关系旁边，A 与 B 的联系在列表里逐行可见 |
| 自动填表独立 | 一级按钮 + 弹窗改名 + 一键追评（fill-all） | 入口常驻、一键全填 |

## 四、关键取舍（为什么选 A 不选 B）

- **性格写库用「合并」而不是「覆盖」**：AI 填满返回的性格 JSON 可能没带原有五维，整体覆盖会丢掉用户手填的东西；合并 = 已有的留下、缺的补上，最安全。
- **自动分类从「四路并行」砍成「单路简单分组」**：四维是某类特定题材的特化，通用小说用不上还慢（四路 = 四次 LLM 调用）；简单分组一路调用、3-6 组，符合你说的「不用太复杂、不用分太多类别」。
- **关系图从右栏搬进角色卡，而不是两处都留**：两处都留会数据展示重复、维护两套入口；搬走删除更干净，且角色卡编辑时看关系图最顺。
- **章节级自动填表（babylore）检测角色关系本轮没做**：章节填表引擎只写「世界书表格」，不写角色卡；让它在填表时同时检测角色关系需要跨两个系统改协议，风险大，本轮先让角色卡层的 AI 填满/扩展把关系检测出来，章节级联动留待下一轮（诚实标注，不假装做了）。
