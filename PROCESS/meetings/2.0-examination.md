## 一、方法论与 9 维度定义

马斯克五步算法（顺序不可颠倒）：
1. **质疑需求**：每条功能必须回答「它为什么存在？谁需要它？」
2. **删除**：删掉不增加核心价值的一切（删到过度再补回 10%）。
3. **简化 / 优化**：前两步完成后才做。
4. **加速**：缩短循环时间。
5. **自动化**：最后才考虑。

9 维度（每个功能逐条打标：✅强 / ⚠️中 / ❌弱 / 🔁重复 / ❓存疑）：

| 维度 | 含义 |
|---|---|
| 1. 实用性 | 是否真正解决写手/用户的痛点 |
| 2. 落地性 | 代码是否真的可用、接线是否通、是否经实测 |
| 3. 可靠性 | 边界/异常/并发下是否稳定，有无静默失败 |
| 4. 关联性 | 是否贴合「AI 辅助长篇小说创作」核心目标 |
| 5. 效率性 | 是加速还是增加点击摩擦/认知负担 |
| 6. 是否重复性 | 与既有功能是否重叠（白痴指数最高的浪费） |
| 7. 必要性 | 没有它产品是否残缺（删除测试） |
| 8. 上下游联通+自我拷问 | 数据从哪来、到哪去、逻辑是否自洽 |
| 9. 马斯克代入双视角 | 代入「用户（要快且不出错）」与「写手（要人设/世界观/伏笔一致、要节奏）」复盘写作技法后对此功能的判断 |

## 二、按钮 → 效果全景图（独立摸底）

**顶栏 Toolbar**：生成大纲 / 章节摘要 / 导入章节 / 编辑文风 / 自动化设置 / 导出 / 备份 / 返回首页。
**顶栏第二行**：大纲(窄屏) / 侧栏(窄屏) / 项目设定(齿轮)。
**左栏 LeftPanel**（6 主 Tab：角色/世界/大纲/故事线/规则/摘要大纲）：新建章节·小节 / 回收站恢复 / 批量模式 / 载入示例 / 写章(故事线入口)。
**中栏 CenterPanel**：版本历史(回滚) / 章纲折叠·轻量章纲·抽卡分镜 / 生成重写·微调·批量写作·游戏模式 / 目标字数 / 实体彩色徽章(点→编辑)。
**生成后统一分析面板 PostGenPanel（8 Tab）**：章节提取 / 情节 / 废词检测 / 逻辑自查 / 本地蒸馏 / 审校 / 文风 / 安全。
**右栏 RightPanel（4 TopTab）**：AI助手(AIChatBar) / 实体(实体追踪·未收尾线索·一致性基线) / 工具箱(9 项) / 统计(总字数·角色·词条·节点 + 叙事能量曲线·生成延迟·节点监测 + 上下文监控)。
**独立路由页**：游戏模式 `/game/[nodeId]`、结构化表格 `/tables`、创意工坊 `/workshop`。
**弹窗群**：CharacterDialog / LorebookEditDialog / StyleEditor / ImportWizard / OutlineDialog / AutomationSettingsDialog / ProjectSettingsDialog / BuildConfigDialog / MemoryDecayDialog / ProjectConfigPanel / ExportDialog / BackupDialog / ConflictPanel / DrawCards / PreGenConfirm / RefineDiffModal / SaveConflictModal / OnboardingModal。

**结论**：入口极度分散——同一动作（如「生成大纲」「新建角色」「AI 对话」）在 Toolbar、左栏、中栏、右栏工具箱、故事线工作台**多处出现**。这是首页「认知负荷」白痴指数最高的地方。

## 三、逐功能 9 维拷问

### A. 写作核心链路

**A1 生成/重写（CenterPanel「生成/重写」→ PreGenConfirm → /api/generate/write）**
- 实用性✅ 落地性✅ 可靠性⚠️(流式 SSE，中断靠 abort；旧 dev server 僵死会 503) 关联性✅ 效率性✅ 重复❌ 必要性✅ 联通✅(落库 storyNodes.content + 自动提取 + 摘要 + 宝宝流填表 + 记忆召回全链路) 双视角✅。

## 五、可靠性 / 上下游联通问题清单（带依据）

1. **角色对话会话记忆进程内存**（C2）：`getRecentContext` 用内存 Map，30min 过期、重启即失、多用户串号。→ 应落库 `ChatSession`。
2. **旧 dev server 僵死 503**（环境）：跨会话长驻进程连接池僵死，热重载可缓解但根治需重启。→ 文档化重启流程。
3. **SSE 后处理静默降级**（page.tsx `postprocess_skip`）：摘要/审校失败仅 toast 不阻断，但用户可能不知摘要缺失。→ 保留降级，但需在章节点明确标记「未摘要」。
4. **stylecard PUT 非可空字段 null**（E1，已修 v1.9）：路由对非可空 Float 传 null 致 ValidationError，被 jsonError 误报为「数据库未启动」。→ 已修，加单测防回归。
5. **废词/逻辑/审校四套质检结果离散**（D3-D6）：各自 SSE 事件，UI 拼接，无统一质量评分聚合。→ 质量中心应聚合为一分。
6. **导入逻辑**：`autoCreateEntities` 已关闭（v1.8 一期），但历史世界书垃圾风险仍在。→ 保留关闭，导入后提示清理。

## 六、马斯克代入双视角 · 写作技法与方法论复盘

**代入用户（要「写得快且不出错」，不要被按钮淹没）**：
- 用户打开 novel-forge 想的是「把脑子里的故事变成字」。最值钱的是 A1 生成/重写 + B2 故事线 + C1 角色。其余 30+ 入口是认知噪声。
- 第一性原理结论：把**核心三件套做成零摩擦主路径**，其余功能收进「进阶」且与核心联动，而非平铺。
- 用户不需要自己判断「抽卡分镜 vs 轻量章纲 vs 生成大纲」——产品该替他决定层级。

**代入写手（要人设/世界观/伏笔一致、要节奏、要风格统一）**：
- 写手最怕：写到 50 章人设崩了、伏笔忘了收、文风飘了。novel-forge 的**真正护城河**是 C4 结构化表格 + F1 摘要大纲 + B2 因果链 + E1 文风 + F4 记忆衰减——这些保证「长书一致性」。
- 写作技法复盘：好小说靠「人物在压力下的选择 + 伏笔的精心铺设与回收 + 节奏的张弛」。novel-forge 已用 因果链(推进/卡点/分支)、未收尾线索、叙事能量曲线 覆盖了技法骨架，这是对的。
- 写手视角对每类功能的判断：
  - 角色对话/附身(C2)：✅ 试戏极有用，但记忆要落库。
  - 冲突推演(D8)：✅ 破局灵感，但别让它替写手决策。
  - 游戏模式(G1)：⚠️ 好玩但易让写手偏离「写」。若做，应能从游戏互动导回正文（目前单向）。
  - 四套质检(D3-D7)：✅ 去 AI 味+逻辑校验是网文命脉，但合一更清爽。

**产品定位裁决（需董事会定调）**：novel-forge 应明确为「**长篇小说 AI 写作工作台**」，核心闭环 = 故事线/角色/世界书(输入) → AI 生成(处理) → 提取/蒸馏/摘要/质检(回收) → 一致性保障(输出)。游戏模式/创意工坊是**卫星功能**，不进主闭环。
