## 四、两个 P0 bug 根因与修复（本轮已修，待复检确认）
- **T1 summarize 500**：`src/app/api/generate/summarize/route.ts:67` 把 LLM 返回的自由文本 `characterStates`（如「林逸：疲惫，舰桥，决定继续探索」）当 JSON `JSON.parse(...)` → 必抛 SyntaxError → catch → 500。修复：改为 `raw: characterStates`，对齐全站约定（post-processor.ts、apply-extraction 均存 `{ raw: ... }`）。
- **T2 refine 截断**：refine 调 `writeSection` 时传 `targetWordCount = targetWords`（增量，默认 500）。`resolveMaxTokens` 按 `targetWordCount*1.6` 放大预算；但 refine 要**重输出「已有正文 + 增量」**（完整修改后版本），预算只覆盖增量 → 在已有正文长度处被截断、增长 0。修复：refine 传 `existingContent.length + targetWords`（完整输出字数），cap 5000 字（≈8000 token）防超模型 `max_tokens` 硬上限。

## 五、待裁决功能清单（董事会核心议题）
请用第一性原理对以下 11 项裁决：是否解决真实用户痛点？是否绕路 / 画蛇添足 / 傻子功能？
1. **写章 write** — SSE 流式生成新章节
2. **续写 continue** — 自动建下一节点续写
3. **精修 refine** — 修改 / 续写已有正文
4. **章节摘要 summarize** — 压缩为中期记忆（无限续写的关键）
5. **限流 rate-limit** — 内存滑动窗口（generate/refine/continue 10/min，import 5/min，settings 3/min）
6. **自动填表 babylore** — 正文→世界卡自动提取
7. **伏笔检测 foreshadowing** — 收束率幂等重算
8. **游戏开局 game/start** — AI 叙事 + 选项分支
9. **导出 export** — markdown/txt/html/epub/docx 五格式
10. **导入 import** — 外部文本→项目（幂等锁 + 逐章校验）
11. **删节点 delete** — 删除章节节点

## 六、裁决标准（马斯克第一性原理 + 用户痛点）
- 该功能是否服务「本地作者高效写出连贯好小说」核心目标？
- 没有它，用户是否被迫用更差的方式绕路？
- 它是否增加理解 / 维护成本却无对应收益（过度工程）？
- 单用户本地场景下，某些「防滥用 / 多人协作」设计（如限流）是否必要？
- 游戏模式：AI 小说平台加「游戏开局」是核心需求，还是旁支炫技（傻子功能）？

## 七、输出要求
每位人格独立产出报告：对 11 项功能各给「有意义 / 待优化 / 傻子功能」裁决 + 一句话第一性原理理由。过半数「傻子功能」入砍除清单；「待优化」入改进清单。Chair（tri）整合。
