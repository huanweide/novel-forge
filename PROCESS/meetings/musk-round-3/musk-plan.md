# 马斯克 Round 3 产品计划 · Novel Forge 确认流程自动化

> 马斯克视角（基于公开言论推断，非本人观点）。白痴 CEO 制度：马斯克全权提计划，可删改新增任何功能，不限权利；执行团队跑 maxloop 直到马斯克体验满意。
> 审视基准：HEAD = v0.46.91（批量确认本卷已落地，质量护栏阈值 60）。

## 第一性原理审视

当前确认流程：`drafting → pending_confirm → confirmed → project_confirmed`，每章要人点 4 个按钮（submit/diagnose/confirm/reject）。这是把人类当审批流水线。

**白痴指数拆解**：
- 一章正常文本，六维质量分析器 1 秒内打 90 分。
- 人类点 4 个按钮 + 阅读，至少 30 秒/章。
- 12 章书 = 人类 6 分钟纯点击，AI 分析 12 秒。
- 人类确认环节的白痴指数 ≈ 30。这是最大的流程浪费。

**五步算法应用**：
1. 质疑需求：每章必须人工确认？——不。只有「质量分 < 阈值」或「检测到严重问题」的章才该让人看。
2. 删除：删掉「逐章审批」的强制交互，降级为「异常拦截」。
3. 简化：确认 UI 收敛为「放行 / 拦截清单」二元。
4. 加速：生成即并行质量分析，循环时间压到物理极限。
5. 自动化：Auto-Confirm——AI 自动放行合格章。

## 功能清单（按杠杆排序）

### #1 Auto-Confirm（智能自动确认）— 最高杠杆
- 新增「智能审阅模式」开关（默认开）。开启后：章生成完（drafting）→ 自动跑六维质量分析 → 若 `qualityScore >= 阈值(默认60)` 且无结构错误 → 自动 `pending_confirm → confirmed`（并触发自动填表 safeFillAfterWriting）；若 `< 阈值` 或检测到严重问题（角色 OOC / 逻辑断裂 / 重复生成 / 正文为空）→ 置 `blocked` 挂起，进人工异常处理队列。
- 保守用户可关掉智能审阅，回到逐章点按钮（兼容现有流程）。
- 阈值可配，复用现有 `QUALITY_PASS_THRESHOLD = 60` 护栏逻辑。
- 落点：章生成写入后新增 auto-confirm 副作用；新增 `POST /api/story/nodes/auto-confirm` 端点（单章/批量），与批量确认端点共享质量护栏函数。

### #2 一键全书智能交付
- `POST /api/projects/[id]/auto-confirm-all`：扫描全书 pending_confirm 章 → 合格自动放行、不合格进 blocked 清单 → 返回 `{confirmed[], blocked[], summary}`。
- 前端整本确认入口升级为「智能交付」：先自动跑，再给 human 一张「拦截清单」做最终决策（reject/force-confirm）。
- 把「12章×4按钮」压缩成「1次扫描 + 1张清单决策」。

### #3 生成循环时间压缩
- 章生成即并行触发质量分析（post-processor 已写 qualityScore，复用即可），不阻塞主流程。
- 流式输出：确认栏实时显示质量分进度，不等整章写完才出结论。
- 这一步依赖现有 narrative-energy / generation-metrics 计时埋点，主要是编排优化。

### #4 UI 减法（继续 v0.46.86 但未够狠）
- 中栏 ChapterConfirmBar：智能审阅模式下，合格章不弹 4 键，只显示「已自动确认 ✓」+ 异常才显操作。
- 右栏 MonitorPanel 确认看板：加「自动放行率」指标，让人类一眼看到 AI 替他干了多少。

### #5 存在主义锚定（产品叙事）
- Novel Forge = 人类故事的文明备份。每条已确认故事线是文明资产。
- 融入首页 hero 文案 + 关于页。不做功能，做叙事。优先级最低，Round 3 末尾轻量落地。

## maxloop 迭代纪律
- 每轮实现 1-2 项 → tsc 门禁 → 双 changelog 升版 → commit → 代理 push → 记忆回写 → e2e 复测。
- 马斯克（模拟体验）验收：满意则进下一项；不满意给具体不满点 → 下一轮修。
- 验证铁律继承：沙箱无 Chromium，浏览器视觉不目测；真实 LLM 调用 + API 闭环验证。

## Round 3 验收标准（马斯克体验满意的定义）
1. 开智能审阅后，生成 12 章正常书，人工点击次数 = 0（合格章全自动确认 + 自动填表）。
2. 注入 1-2 章低质/空正文，这些章自动进拦截清单，不被蒙混放行。
3. 一键全书智能交付：1 次操作出「放行 N / 拦截 M」清单，human 只对 M 做决策。
4. UI 不啰嗦：合格章确认栏一句话带过，异常才展开操作。
