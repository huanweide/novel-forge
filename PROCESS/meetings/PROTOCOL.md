# Novel Forge 会员股东无限会议（maxloop QA 迭代）

> 目标：用 6 位「会员股东」人格，每人拥有自己的小说项目、负责一类功能透镜，轮流出任「用户体验 + 监控后台」，
> 每轮体验功能、对照预期、提出具体优化建议（文件:行号 + 严重度 + 修法），由 Chair(主代理) 实现并验证，再开下一轮复验+挖新坑。
> 循环直至每位股东无建议，至少 5 轮、无限 token。

## 会议循环协议（L0 调度 / L1 收集 / L2 实现 / L3 复验）
- **L0 调度**：每轮建 `round-N/` 目录；并行 spawn 6 位股东 subagent（各自 Write 报告到 `round-N/<股东>.md` 并回总结）。
- **L1 收集**：每位股东只读分析（读源码 + 跑相关 vitest + 对照 CHANGELOG/WORK_REPORT 预期），产出 2–4 条具体发现（P0 阻断 / P1 重要 / P2 轻微），禁止空谈。
- **L2 实现**：Chair 汇总优先级，实现 Top 修复，跑 `SAFE_DELETE_DISABLE=1 npx tsc --noEmit` + 相关测试 +（可行时）真实 LLM 验证。
- **L3 复验**：下一轮股东先复验上轮修复（回归），再挖新坑；直到全员无 P0/P1 建议则该轮收敛。

## 六位会员股东（唯一透镜，不重叠）
1. **股东·墨白（写实悬疑《龙陨之地》）** — 透镜：写章流程 + 自动填表/自检/防重复/归属。关心填表零错名、写章→填表联动、短章/空章边界。
2. **股东·青砚（玄幻大世界 200+ 词条）** — 透镜：三卡检索词边界 + 召回注入 + 自动建卡去重 + 禁词扫描。关心「林」误命中、繁简/错字变体重复、大世界召回截断。
3. **股东·阿游（互动游戏小说）** — 透镜：游戏模式流式 + 背包归属 + 世界卡物品联动 + 与主线一致性。关心 owner 归属、CI| 解析健壮性、物品→世界书补建、流式错误。
4. **股东·工坊（数据迁移控）** — 透镜：备份导出/导入选择 + 导入合并 + 预设应用 + 正则规则。关心 include 过滤正确、合并不覆盖、预设应用、正则 UI。
5. **股东·清览（UI/无障碍）** — 透镜：关键词高亮 + 名称高亮 + 暗色下拉 + 弹窗滚动 + 书卡可见 + 响应式。关心高亮重叠/嵌套、对比度、溢出、移动端。
6. **股东·磐石（性能/监控）** — 透镜：填表 token 消耗 + 召回上下文大小 + 防重复效率 + 监控统计。关心 O(n²) 扫描、大项目上下文爆量、进度反馈、token 浪费。

## 诚实边界
- 沙箱直连 DeepSeek 超时（须走代理 127.0.0.1:7897）；应用 fetch 不读 HTTP_PROXY，靠 proxy-setup.mjs。股东「体验」= 读码 + 跑测试 + 对照预期，非真跑整链。
- dev 为受管进程（PID 37396）不盲目重启；真实交互由用户在本地 `NODE_OPTIONS="--import ./proxy-setup.mjs" LLM_PROXY=http://127.0.0.1:7897 npm run dev` 后验收。
- 每位股东发现须基于真实代码/测试证据，禁止编造；Chair 实现须 tsc 零错误 + 测试绿 + 双 changelog + 代理推送。
