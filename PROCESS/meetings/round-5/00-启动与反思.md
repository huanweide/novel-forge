# Round-5 启动文档与上轮漏检反思

## 一、本轮目标

按用户指令，对 novel-forge 做基于「云笔 (aixiaoshuojia.cn)」参考站 UI 与功能体系的深度集成与风格统一。重点解决：

1. 折叠/收起问题（面板默认态、信息层级、展开/收起交互）。
2. UI 布局问题（间距、对齐、按钮位置、三栏比例、空状态、响应式）。
3. 功能集成问题（已有功能与参考站相似/重复/缺失模块的合并、联动、写入）。
4. 风格统一问题（配色、圆角、阴影、字号、图标、卡片、开关、主/次按钮层级）。

## 二、上轮为什么漏掉这些问题

### 2.1 评审没看「真实渲染」，只看源码与文本

上轮 MaxLoop 开会子 Agent 主要依靠 `grep` / `Read` 源码，极少（甚至没有）对运行中的 `npm run dev` 页面截图。折叠/布局/间距属于视觉问题，源码里一行 className 看不出来最终效果。

### 2.2 缺少参考基准

上轮没有给出明确的竞品/参考站截图，评审标准是模糊的「好不好用」。没有外部基准，Agent 很容易把「当前已实现」当成「足够好」。

### 2.3 透镜划分太粗，没有「UI/布局」专职人格

6 人格虽然分工，但没有人专门负责「像素级 UI/折叠/空状态/响应式」。布局问题在代码审查中被当成边角料忽略。

### 2.4 Chair 轻信汇报，未亲自截图验证

Chair（我）上一轮收到「已完成」回报后，只跑了 `tsc` 和 `vitest`，没有重新打开浏览器截一张 ChapterConfirmBar 的图，因此没发现交付区仍然臃肿、折叠文案不统一。

### 2.5 集成视角不足

上轮每人只盯自己模块，没人横向对比「参考站有这个，我们有没有」「我们有两个相似入口能否合并」。导致新增 `autoDeliverEnabled` 功能正确，但与之配套的信息层级、折叠、状态提示没有同步优化。

## 三、本轮新增铁律

1. **必须截图**：每个 Agent 在报告中至少附 3 张运行截图（关键路径），用 `capture_screenshot` 或浏览器真机截图。
2. **必须有参考基准**：所有 UI/交互判断以 14 张云笔截图为准，逐项打钩。
3. **新增 UI 布局透镜**：清览人格本轮专职负责「像素级 UI/折叠/空状态/布局」审查。
4. **Chair 必须亲自看图**：不只跑门禁，要逐屏打开关键路径并肉眼检查。
5. **横向集成表**：任何改动前，先填「参考站-现有功能对照表」，确认是「集成/合并/删除/新增」哪一种。
6. **改动必须联动写入**：新增 UI 开关/入口必须有对应的 API 字段 + Prisma 字段 + 默认值 + 测试。
