## 2026-08-01 · 给 AI 装一个「做完就写人话图纸」的开关

### 这次干了啥
斯瑞希望：以后我每做完一件完整的小事（写个小功能、改个小点、做个调研），就自动生成一份「连不懂技术的人也看得懂」的说明，永远留在右侧产出面板能翻到，而且越攒越多、绝不删旧的。

### 为什么要它（第一性原理）
AI 干完活，通常只丢给你一堆代码或一句「搞定了」。代码是给机器看的，人看不懂；而且下次对话 AI 自己都忘了上次怎么做的。这就像工人盖完房只留一堆砖头，不画图纸——你既看不明白，也没法照着再盖。
所以要在「做完」那一刻，立刻把「思维图纸」用大白话写下来。类比：每道菜炒完，厨师顺手在厨房墙上贴张便签——放了啥、为啥先放油再放菜、火大了怎么救。下次照着来，外人也能看懂。

### 怎么落地的（用了什么、效果）
1. **把开关装到「每次开工都会读到的地方」**：AI 有个跨对话一直跟着的「长期记忆」文件（`~/.workbuddy/MEMORY.md`），每次开聊都自动读进来。这就是能一直生效的「预设」。我把这条新规则钉在它最前面，标成「最高优先级」，让它压过其他临时任务指令。
2. **建一本永远不撕的笔记本**：本文档（`novel-forge/PROCESS/WORK_REPORT.md`）就是那本施工日志，规定只能往后写、不许删旧的——像工地越来越厚的施工日志。
3. **写完立刻亮出来**：每次干完活，我把新的一段写进本文件，再用系统的「呈现」功能把它推到对话产出下方，你当下就能看见；跨对话时文件还在项目里，随时能翻。

### 试过的方案 / 为什么没选别的（诚实记录）
- **想直接改 WorkBuddy 平台自带的「系统提示词」？** —— 那是平台内部文件，AI 在对话里改不了，硬改有风险、还可能破坏其他功能。所以改用「在长期记忆里钉最高优先级规则」这个我能安全控制的等效办法，行为效果一模一样：每次对话都加载、且压过其他指令。
- **覆盖式笔记（只留最新）而非追加？** —— 覆盖会让旧经验消失，违背「可复现、能回忆」的初衷；追加才能看出思路是怎么一步步演进的。

### 关键取舍（工具 A 为何不选 B）
- 选「人话 + 类比」而非「堆术语」：术语像密码，记不住；类比能让人脑子里「浮现」画面。比如把「系统提示词」比成「每次开工前老板发给你的工作须知」，把「长期记忆」比成「工人随身带、天天翻的笔记本」。
- 选「完成后才写」而非「做一半就写」：半截子工作结论可能是错的，写了反而误导；必须 100% 做完、拿到确切结果才触发。

## 2026-08-01 · 给小说工坊加一个「首次进入引导弹窗」（v0.45.6 / P2-3）

### 这次干了啥
按竞品借鉴计划（PROCESS/06）推进，挑了里面最低成本的一项 P2-3：给小说工坊的工作区加一个**首次进入时的新手引导弹窗**——一打开就弹张卡片，用大白话介绍 5 个核心功能（自动化填表 / 抽卡剧情 / 拆解大纲 / 游戏化 / 竞品借鉴），看完点「开始创作」就关掉，以后不再弹。

### 为什么需要它（第一性原理）
小说工坊功能很多（AI 写作、抽卡、拆解、游戏化……），但新用户一进来面对满屏按钮，容易懵、不知道从哪下手。竞品都有个「欢迎 + 功能引导」的入场。类比：进一家大餐厅，有人递来菜单还顺手推荐三道招牌菜，比你自己瞎翻舒服得多。这个弹窗就是那个「门口迎宾」。

### 怎么落地的（用了什么、效果）
1. **不自己造轮子，直接复用现成的「弹窗模板」**：项目里早就有个统一 `Modal` 组件（相当于公司标配的 pop-up 模板），它自带一堆麻烦事都帮你处理好了——焦点陷阱（键盘 tab 不会跑出弹窗）、按 ESC 关闭、点灰色遮罩关闭、弹窗时锁住背景滚动。我只往里填内容，省事又不会漏掉无障碍细节。
2. **用浏览器本地标记记住「看过了没」**：用了 `localStorage`（相当于你家门禁的「已打卡」小本子，存在你自己浏览器里，不上传服务器）。第一次来没标记 → 弹；关掉时写个 `nf_onboarded_v1=1` 标记 → 以后再来就不弹。纯前端，没碰数据库，稳。
3. **做了防御**：万一用户浏览器禁用了本地存储（读不到小本子），我用 try/catch 包住，静默忽略——弹窗不弹就算了，绝不让整个页面崩。

### 试过的方案 / 为什么没选别的（诚实记录）
- **从零自己写一个弹窗？** —— 要重复处理焦点陷阱、ESC、遮罩、滚动锁定一堆细节，容易漏。直接复用 `Modal` 既省事又合规，属于「站在之前自己的肩膀上」。
- **用后端数据库存「已引导」状态？** —— 杀鸡用牛刀。一个「看没看过」的标记，浏览器本地记就够了，没必要惊动数据库。
- **每次进都弹？** —— 老用户会被烦死。所以做成「首访才弹 + 本地标记」，只打扰一次。

### 关键取舍（工具 A 为何不选 B）
- 选「复用 Modal」而非「自写弹窗」：复用 = 不重复踩坑 + 风格统一。
- 选「localStorage 标记」而非「后端记录」：本地标记零成本、零风险。
- 选「首访才弹」而非「常驻」：引导是一次性认知负担，看过即走。

## 2026-08-01 · 给角色卡加「性格三层」创作字段（v0.45.7 / P2-1）

### 这次干了啥
继续按竞品借鉴计划推进，挑了 P2-1：给角色编辑弹窗的性格区，新增**三个由浅入深的创作框**——
- **表层 · 对外展现**：旁人眼里他是怎样的人（比如「温和有礼、慢条斯理」）。
- **中层 · 日常互动**：熟悉后才露出的另一面（比如「其实很要强、怕被看轻」）。
- **内核 · 本质驱动**：最深处那点本性/创伤/欲望（比如「童年被弃导致极度缺乏安全感」）。

填了之后，AI 写这个角色时就会自动按这三层去塑造，人物更立体、不扁平。

### 为什么需要它（第一性原理）
好小说的人物不能只有「一句话标签」。现实里人都是分层的：你在外人面前是一副样子，朋友面前是另一副，最深处还藏着自己都不愿承认的东西。如果只给 AI 一个扁平的「性格：外冷内热」，它写出来的人物就容易脸谱化。
类比：给演员说戏，不能只说「你演个好人」，得说「他在外人面前笑脸迎人（表层），其实心里算计得很清楚（中层），根源是小时候穷怕了（内核）」——演员才知道怎么演出层次。这三层字段，就是给 AI 的「说戏三层法」。

### 怎么落地的（用了什么、效果）
1. **把三层直接塞进角色已有的「性格抽屉」里**：角色卡本来就有一个存性格的「万能抽屉」（`personality` 字段，类型是 Json，相当于一个能随手塞任意小纸条的收纳盒，不用提前规定格式）。我往这个抽屉里加了三张新纸条：`surface` / `middle` / `core`，分别对应三层。**关键是：不用改数据库结构（零迁移）**——Json 抽屉本来就能多塞几张纸条。
2. **保存时不丢旧东西**：原来性格区是用一段文字解析出来的。我改造保存逻辑，用「展开运算」`{ ...旧的, surface, middle, core }`——像把旧抽屉整个搬过来，再把三张新纸条轻轻放进去，旧的纸条一张不少。
3. **AI 自动就能读到**：项目里有个现成的「翻译官」函数 `safeJoin`，专门把角色性格抽屉里的纸条内容拼成一段文字喂给 AI。它本来就会把所有纸条的值拼起来——所以我新加的三张纸条**不用改任何装配代码，自动就进了 AI 看到的「性格：…」那段话里**。等于免费搭了顺风车。
4. **AI 自动补全不打扰你手填的**：角色卡有个「AI 帮我填满」按钮，它会重写性格。我特意让它只回填它懂的旧维度，**绝不碰你手填的三层**——你辛辛苦苦写的内核，不会被一键覆盖掉。

### 试过的方案 / 为什么没选别的（诚实记录）
- **给数据库加三个正式字段（surface/middle/core 各一列）？** —— 要改 Prisma schema、跑迁移、动线上数据库结构，牵连大、风险高。而 `personality` 本来就是 Json 万能抽屉，往里塞三张纸条零成本。选了后者。
- **单独做一个「三层性格」弹窗/页面？** —— 过度设计。三层本来就是性格的一部分，直接放在现有「性格详析」区块下方最顺手。
- **手动把三层拼进提示词装配层？** —— 没必要。`safeJoin` 已经会把 Json 抽屉里所有纸条拼进提示词，我只要把纸条放进去就自动生效。

### 关键取舍（工具 A 为何不选 B）
- 选「并入 Json 抽屉」而非「加三列」：Json 灵活、零迁移、向后兼容。
- 选「展开运算保留旧字段」而非「整体覆盖」：覆盖会让用户之前填的主导/驱动/矛盾等丢失。
- 选「借 safeJoin 自动注入」而非「手写装配」：复用现成链路 = 改动最小、最稳。

## 2026-08-01 · 删 P2-2 + 导出弹层一键复制全文（v0.45.8）

### 这次干了啥
两件事：
1. 按斯瑞明确指示，把 PROCESS/06 计划里的 **P2-2「每日写作目标可视化」整项删除**——这个功能不做了。
2. 顺手给导出弹层加了一个 **「复制全文 Markdown」按钮**：点一下，整本书的稿子就被复制到你电脑的剪贴板，你可以直接粘贴到微信、Word、聊天框，不用先下载文件再打开。

### 为什么这么做（第一性原理）
- **删 P2-2**：斯瑞判断这个功能是多余的。小说工坊早就有「数据看板」（MonitorPanel）和运行统计接口（`/api/stats`），作者想看写作量、进度，那里面已经有了。再单独做一个「每日目标 + 进度环」，等于在同一面墙上挂两块功能重复的钟——纯属浪费。第一性原理：东西够用就别重复造，免得越加越乱。
- **加复制按钮**：作者写完稿子，最常见的一个动作是「发给别人看 / 贴到别处整理」。原来的路子是「点导出 → 下载一个 .md 文件 → 打开 → 复制」。多绕三步。直接给个按钮「一键复制」，就像复印机旁放了台「随手印」，省得你先把纸存进抽屉再拿出来印。

### 怎么落地的（用了什么、效果）
1. **复制按钮 = 复用现成的「取稿接口」+ 浏览器自带「粘贴板」**：
   - 导出全文的活儿，v0.45.0 那轮早就做好了——有个网址（接口）`/api/projects/[id]/export?format=markdown`，访问它就返回整本书的 Markdown 文本。
   - 我新加的按钮就干一件事：用前端 `fetch` 去敲这个网址，把返回的文本拿回来，再调用浏览器自带的 `navigator.clipboard.writeText(文本)` 塞进剪贴板。全程没碰数据库、没加任何新库。
2. **加了三重状态提示，但不烦人**：点下去先显示「复制中…」，成功了闪一下「已复制全文 Markdown ✓」，万一失败（比如浏览器禁了剪贴板）就提示「复制失败，请改用导出文件」。提示 2.2 秒自动消失，不挡着你继续写。
3. **砍 P2-2 干净利落**：在计划文件里把那一项整段划掉，并注明「用户确认不做」，同时在进度清单里打个「已移除」标记，避免以后哪次对话误以为它还没做。

### 试过的方案 / 为什么没选别的（诚实记录）
- **复制功能要不要走后端新接口？** —— 不用。现成的导出接口已经能把全文文本吐出来，前端直接 fetch 就行。再写个后端接口是脱裤子放屁。
- **要不要引入复制库（如 clipboard.js）？** —— 不用。现代浏览器原生 `navigator.clipboard` 已经够用，引库反而多一个依赖、多一份体积。
- **P2-2 能不能「先留着以后做」？** —— 斯瑞明确说不做，我就从计划里彻底删掉，而不是留个 TODO 占位。留着会被误读成「待办」，干净删除才是真闭环。

### 关键取舍（工具 A 为何不选 B）
- 选「复用导出接口 + 原生剪贴板」而非「新接口 / 引库」：零新增、零风险、改动最小。
- 选「彻底删除 P2-2」而非「标记暂缓」：用户已拍板不做，删除避免后续混淆；若以后真要，重新加回计划即可。
- 选「状态提示 2.2s 自动消失」而非「常驻提示 / 弹窗」：复制是顺手动作，给个即时反馈就够，绝不打断创作流。
