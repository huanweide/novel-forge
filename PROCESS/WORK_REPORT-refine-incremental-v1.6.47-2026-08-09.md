# v1.6.47 修复 refine 长章截断根因（续写意图增量拼接）

> 费曼式工作单元报告 · 面向零基础读者 · 用大白话讲清「怎么运作」

## 一、干了什么（一句话）

novel-forge 的「精修/微调」功能，在章节已经写长之后，会让用户白等几十秒还拿到失败。v1.6.47 把这个故障从根上修掉了——改成「只让 AI 写新增的那一小段，程序自动接回原文」，不再要求 AI 把整章重抄一遍。

## 二、为什么这么做（第一性原理）

**一个生活化类比**：你让助手在已经写好的 3000 字文章末尾「再补 500 字」。如果要求助手先把这 3000 字原封不动抄一遍、再写 500 字——助手可能写到一半纸不够（被截断），你拿到半篇残稿，前面 3000 字白抄了。更聪明的做法是：助手**只写那 500 字新增**，你（或程序）自己把新增贴到原文后面——又快又不会丢原文。

novel-forge 之前的 refine 就是「抄全文 + 续写」模式。章节一长，AI 输出逼近字数上限被截断，用户白等。这个故障不是猜的——是 v1.6.46 真跑时坐实的（第二次 refine 被 `length` 截断，357 token 戛然而止；第三次才成功）。

**为什么这事值得修**：refine（精修/微调）是用户最高频的操作之一。每修一次长章截断，就等于每天让大量用户白等几十秒拿到「请重试」。

## 三、用了什么方法 / 工具，效果如何

**1. 侦察根因（读源码，不靠猜）**
- 读 `src/app/api/generate/refine/route.ts`：发现提示词铁律要求模型「完整重输出已有正文全文（最长 3000 字切片）+ 追加续写」。
- 读 `orchestrator.writeSection` 与 `resolveMaxTokens`：确认预算被设成「原文长 + 续写字数」，长章时 AI 实际输出随机逼近上限，必被 `length` 截断。
- 现有 L5-02/L5-06 保护只在「截断/缩短」时保留原正文——等于让用户白等后拿到失败提示，没修根因。

**2. 修复方案：意图分流 + 增量拼接（修因不修果）**
在 refine 路由加一个判断：用户指令是不是「纯续写」（继续写 / 续写 / 接着写 / 补字 / 展开 / 推进剧情 等，且不是「精准修复」）。
- **是纯续写** → 走「增量模式」：
  - 提示词改成：只从断点无缝衔接续写约 N 字，**严禁复述已有正文**。
  - 预算只给续写字数（`targetWords`），不再叠加原文长度——从根上消除「重输出全文撞上限」。
  - 落库前程序把「原文（去尾部空白）+ 双换行 + 增量（去头部空白）」拼起来，保证衔接自然。
- **是修改/精准修复** → 保持原「全文重输出」契约不变（有 L5-02/L5-06 保护，安全）。

**3. 安全护栏（绝不丢用户已写内容）**
- 增量太短（模型几乎没写）或增量被截断时：**丢弃不完整增量、保留原正文**，绝不拿残片覆盖用户章节。
- 增量模式在 done 事件里把 `budgetCapped` 强制置 false，避免前端误报「预算不足」。

**4. 端到端实证（真跑，不是嘴说）**
- 用 `continue` 在星辰项目自动建一个 1120 字临时章节（order=4）。
- 对该节点跑 refine 增量续写（指令含「续写」，命中增量模式）。
- 结果：
  - 模型**只生成 383 token 增量**，没有重抄 1120 字前文（对照 v1.6.46 同样指令被 `length` 截断白等）。
  - `done.wordCount=1707` = 原 1120 + 增量 587，拼接正确。
  - 落库 `contentLen=1707` 验证通过；拼接衔接处为「决定去听。\n\nD7甲板的门禁亮」——原文末尾 + 双换行 + 增量开头，自然无缝。
  - 宝宝流自动填表 8 行全 applied，无 error、无截断告警。
- 测试完软删临时节点，星辰回到 3 个干净节点。

**5. 门禁**
- `SAFE_DELETE_DISABLE=1 npx tsc --noEmit` → 0 错误。
- `npx vitest run` → 35 文件 323/323 全绿。

## 四、关键取舍

- **为什么不改「修改类指令」也走增量？** 因为「修改」可能改文章任意位置，必须让 AI 看全文才能改；增量只适用于「在末尾续写」。修改类保留原逻辑 + 保护，安全零回归。
- **为什么不是「加大 max_tokens 上限」？** DeepSeek 有硬上限且输出随机性强，加预算只是推迟问题、不根治；增量模式是修因（让 AI 根本不用抄前文）。
- **诚实边界**：测试用的临时章节已软删，星辰数据干净；增量模式对「修改类指令」不生效（仍走全文重输出、有保护），长章修改类防截断留后续迭代。

## 五、照做即可复现

1. 启动 dev server：`node ./node_modules/next/dist/bin/next dev -p 3001`。
2. 找一个已有正文的项目节点，调用：
   `POST /api/generate/refine`，body：`{"projectId":"<项目ID>","nodeId":"<节点ID>","instruction":"请基于现有正文自然续写约500字，推进剧情","targetWords":500}`
3. 看 SSE 流末尾的 `done` 事件：
   - `wordCount` 应 = 原长 + 增量（拼接正确）。
   - `token` 计数应远小于「原长 + 增量」对应的 token 数（证明 AI 没重抄前文，增量模式生效）。
   - 若 `truncated:true` 出现，说明增量被截断，此时程序应保留原正文、不污染章节。
