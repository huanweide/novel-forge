## 一、干了什么（一句话）

把小说「跨章一致性引擎」里一处会**静默丢设定**的真实 bug 修掉，顺手把三处解析代码的写法统一了，升到 v1.8.1，双门禁全绿后推上线。

## 二、为什么这么做（第一性原理，不堆术语）

一致性引擎做的事，类比成「给长篇小说配一个不会忘事的编辑」：

- 它先从你写过的章节、角色卡里**抽出一堆事实**（比如「主角林惊羽的瞳色=灰」），存成一张「设定清单」。
- 你写新章时，它把清单塞进 AI 的提示词里，让 AI 别忘了前面的设定。
- 新章写完后，它再拿新章正文和清单比对，找出前后矛盾的地方标红，给你改写建议。

问题出在「抽事实」这一步的去重上。AI 一次可能抽出好几条**一模一样**的事实（比如重复说「瞳色=灰」），存库时会堆垃圾。所以代码里有 `dedupeFacts` 这个「去重函数」——它给每条事实算一个**身份证号（key）**，号相同的就只留第一条。

原来的身份证号是用一根竖线 `|` 把「主体+属性」拼起来的：`林惊羽|瞳色`。这就像用「张三,李四」当编号，但如果有人真名叫「张三,李四」，就会和「张三」+「,李四」撞号。

**真实 bug**：如果某条事实的主体或属性本身含有 `|` 字符（比如角色名「甲|乙」、属性「乙|x」），旧算法会把两条**完全不同**的事实算成同一个号，静默丢掉一条——作者辛苦写的设定就这么没了，而且不报错、肉眼难发现。这正是马斯克说的「白痴指数极高的不该存在的风险」。

第二个问题是「代码 fence 剥离」三处写法不一致。AI 返回的内容常裹在 ```代码块``` 里，程序要先扒掉这层外壳再解析 JSON。三处里有两处只认 ```json，有一处认 json/text/markdown。风格不统一，遇到 AI 用 ```text 包裹时前两处兼容差。纯属重复劳动，顺手收口。

## 三、用了什么方法 / 工具，效果如何

工具：Bash grep/Read 实地排查（本仓库 Grep/Glob 工具在绝对路径下假阴性，禁用）；Python 精确字符串替换改源码（Read 工具对 core 路径偶发假失败，改用 Python 可靠落地）；`tsc --noEmit` 查类型错误；`vitest run` 跑单测。

改动清单（4 个文件）：

1. `src/core/consistency/extractFacts.ts`
   - 去重 key 由 `` `${a}|${b}` `` 改为 `JSON.stringify([a, b])`。JSON 序列化把两个字段包成数组再转字符串，**永远不可能因为字段里含 `|` 而撞号**——因为数组结构本身带分隔语义。
   - fence 剥离正则 ```` /```(?:json)?\s*.../ ```` → ```` /```(?:json|text|markdown)?\s*.../ ````。
2. `src/core/consistency/detectConflicts.ts`
   - 同上统一 fence 剥离为 json|text|markdown。
3. `src/core/consistency/extractFacts.dedupe.test.ts`
   - 新增 1 例回归单测：构造「甲|乙/x」与「甲/乙|x」两条事实，断言去重后仍为 2 条（旧实现会误并为 1 条）。这就是把 bug 钉死的保险。
4. 双 changelog 升版：`src/lib/changelog-data.ts`（LATEST_VERSION / CHANGELOG_BRIEF / VERSIONS 三处）+ 根 `CHANGELOG.md` 头条，标题 v1.8.1。

效果数据：

- `SAFE_DELETE_DISABLE=1 npx tsc --noEmit --incremental false` → **0 错**（关增量缓存防幽灵报错）。
- `npx vitest run` → **41 文件 358 测试全绿**（原 357，加本次 1 例）。
- 零 schema 迁移、零新依赖、纯解析/纯函数层，回归面极小。

## 五、踩坑与实测（反自欺闸门）

1. **BRIEF 拼接污染（已修复）**：第一次用「前缀替换」改 `CHANGELOG_BRIEF` 四行摘要时，只换了开头的 `v1.8.0` 文案、没删掉行尾残留的旧 v1.8.0 正文，导致四行变成「新标题+旧正文」的胡话。tsc 不报错（仍是合法字符串），但语义错误。靠 `grep` 复核发现，已用整行干净替换修正，并复跑 tsc 确认。教训：改长字符串必须整行/整块替换，不能只换前缀。
2. **Read 工具假失败**：对 `src/core/consistency/*` 路径 Read 持续报「文件不存在」，但 `ls`/`cat` 证实文件在。遂全程改用 Bash/Python 读写，规避该工具假阴性。
3. **Write 工具假成功**：本次用 Write 写费曼报告，工具回报成功但文件未落盘（沙箱文件系统未持久化），`git add` 报路径不匹配才发现。改用 Python 直接写文件恢复，已核对落盘。
4. **增量编译缓存幽灵**：`tsc` 默认增量缓存可能报历史幽灵错，本轮按工程铁律加 `--incremental false` 关掉。
