## 一、紧急 Bug 修复（确定性高、先收口）

### A. 墨灵面板重复渲染
**根因（已确认）**：`AIChatHeader` 始终渲染「AI 写作助手就绪 + 我能直接查角色卡… + 统计条 + 墨灵能做什么」；`ChatMessageList.tsx` 第 31–39 行空状态又**独立渲染了一遍**同样的「AI 写作助手就绪 + 我能直接查…」。初始无对话时两者叠在一起。
**修复**：
1. 删除 `ChatMessageList.tsx` 第 31–39 行空状态里的重复就绪文案块（头部已展示）。
2. 统计条若仍出现两种格式（5193 无逗号 / 5,193 有逗号），用 React DevTools 确认 `AIChatBar` 是否被挂载两次；当前源码统计条仅 `AIChatHeader` 一处（`toLocaleString` → 带逗号），无第二处，若真出现双份是运行时双挂载/旧构建问题，需清缓存验证。

### H. 项目设定 UI 溢出不可滚动
**根因（已确认）**：`BuildConfigDialog.tsx` 第 62 行用 `Modal bare`，但 `bare` 分支**不带 `overflow-y-auto`**（只有非 bare 分支带）。面板 `max-h-[90vh]` 截断后内容直接溢出且不可滚动。对照 `ProjectConfigPanel.tsx` 第 150 行显式加了 `overflow-y-auto` 所以能滚。
**修复**：`BuildConfigDialog.tsx` 第 62 行 `panelClassName` 补 `overflow-y-auto`（仿 ProjectConfigPanel）。

### I-1. 分类界面亮度过高
**根因（已确认）**：`RulesPanel.tsx` 的「分类 / 生效范围 / 优先级」用原生 `<select><option>`，展开的下拉面板由**操作系统原生渲染**，不受 Tailwind 暗色变量约束，在暗色主题下呈高亮白底，盖住其他项。`BuildConfigDialog` 的 `<select>` 同病。
**修复**：全局对 `select`/`option` 做暗色适配（CSS `option { background: var(--nv-surface-2); color: var(--nv-text-primary); }` 或改用自定义下拉组件）。

### I-2. 两套"规则"UI 不统一
**澄清（重要）**：项目里**真有两套完全不同的"规则"**，用户把它们混为一谈：
- **(A) 正则后处理规则**（`ProjectConfigPanel`）：字段 `name/pattern/flags/replace`，作用是**生成完成后对正文做正则替换**（如删思维链）。已确认**真实生效**（write/refine/continue 三处均接 `applyRegexRules`）。
- **(B) 创作铁律**（`RulesPanel` 左侧「规则」页签）：字段 `name/content/category/scope/priority`，作用是**注入 AI prompt 当铁律**。
**修复方向**：
1. 明确术语与分区：UI 上把「(A) 后处理规则（清洗正文）」与「(B) 创作铁律（约束 AI）」用不同区块+说明区分，避免用户以为是一套。
2. 统一「新建规则」弹窗风格：使 (A) 新增规则也走与 (B) 一致的弹窗组件（而非当前内联追加行），消除"怪异不匹配"。
3. **按用户要求实测**：加一条 `pattern: <think(?:ing)?>[\s\S]*?<\/think(?:ing)?>`、`replace: 空` 的规则并生成，确认 SSE 出现 `postprocess_regex` 事件、正文被清 —— 验证后向用户报告"正则规则确实生效，但是后处理不是上下文注入"。

## 二、世界卡检索与填表逻辑修复（核心正确性，用户最不满）

### F. 检索规则瞎搞 / 填错名
**根因（已确认）**：
1. **检索端**：`trigger.ts` `matchLoreEntries` 用 `text.includes(key)` 暴力子串匹配，打分 `key.length/fullText.length` 恒趋于 0 无意义，仅按插入顺序取前 N；`recall.ts` 关键列值 `≥2字` 且 `includes` 即召回，**无语义、无边界、无消歧、无相关性排序** → 用户说的"检索规则不合法、极易出错"。
2. **生成端（错名字来源）**：两条自动链路都无"权威名录"硬约束——
   - `babyloreFill`（填 `LoreTable`）：LLM 自由抽取，仅有 prompt 软约束"绝不编造"， hallucination 或同名 `update` 误覆盖即写错名。
   - `entity-auto-creator`（填 `LorebookEntry`）：靠正则启发式检测命名，错检即产生错误词条（如"星辰诀/星辰决"）。

**修复方案**：
1. **召回端——加边界与相关性**：子串匹配改为**词边界**（前后非汉字/标点才命中，避免"剑"在任意语境都触发）；引入真实相关性（如「该词条 key 命中且同段落出现角色/地点」加权），去掉形同虚设的打分公式，改为按命中强度 + 类型排序取前 N。
2. **生成端——加权威名录校验**：`babyloreFill` / `entity-auto-creator` 写入前，先与**既有角色卡 + 世界书已存在条目**做名称相似度比对（相似度过高→合并/更新而非新建；明显冲突→标"待用户确认"而非直接落库）。杜绝"瞎填错名"。
3. **填表机制定位（回应 L）**：`babyloreFill` 已实现，但只填 `LoreTable`（结构化表格）而非世界卡；用户期望"默认开始体的填表机制用来填世界里的东西"。**方案**：把世界卡（地理/功法/物品）的自动抽取结果**回写到对应 `LorebookEntry`**（而非只丢进 LoreTable），并允许用户在**填表面板**里确认/修正（先填后审，不每章盲目生成）。同时补一份"填表机制还能干什么"的设计说明（见第四节）。

## 三、重定位类（结构性，需你确认方向）

### E. 时间线系统
**根因**：时间线是**独立一级视图** + 用户**手工逐章填**自由文本 `worldTime`，纯字典序排序无法排时间先后；世界卡（WorldPanel）**完全没有时间维度**；无任何自动派生。
**方向（按你的逻辑）**：
1. **降级**：时间线不再是一级视图按钮，改为**世界卡内的一个标签页/子视图**（"时间线"作为 WorldPanel 的一节）。
2. **自动派生**：新增"从章节检索时间线"逻辑——写章后从正文/章节标题抽取时间标记（如"天启三年春"），或读取 `storylines` 的时序，自动汇总成时间轴，不要求用户手填。
3. 首页不写时间线（现状本就不写，确认无回归）。

### G. 创意工坊「从创意工坊」联动
**根因**：预设是"工坊 push（应用到项目）+ 一次性拷贝"，项目侧只有零散的 style/正则入口，**无统一的"从创意工坊选"按键**，也没有"弹窗跳转到创意工坊界面"。
**方向（按你的逻辑）**：
1. 在各预设相关的项目配置处（风格/世界书/正则）加**统一「从创意工坊」入口**：点击 → 弹窗列出创意工坊对应类型预设，点选即套用；或按钮"前往创意工坊"直接 `router.push('/workshop')` 并在选完回写 `appliedPresets`。
2. "可自建"保留（上传/内置下拉），但与"从创意工坊选择"**并列成清晰双入口**，不再混在"项目配置"深层。

### J. workspace 一级创意工坊按钮
**修复**：`Toolbar.tsx` 或次级栏加一个一级「创意工坊」按钮 `router.push('/workshop')`，与现有「项目设定/记忆衰减/项目配置」并列（页面本身已完整，只缺直达）。

## 四、游戏模式 + 关键词/物品/语法高亮效果

### B. 游戏模式 start 流式
**根因**：`/api/game/start` 把流式 LLM 缓冲成完整串再 `return json`（非 SSE）；前端 `handleStart` 用 `await res.json()` 一次性取 → 开场慢无打字。action 路由已正确 SSE。
**修复**：把 start 改成与 action 同构的 `ReadableStream` SSE（边生成边 `yield token`，末尾 `game_done` 带 options/entities/items），前端 `handleStart` 复用 `handleAction` 的 reader 循环做打字显示。

### C. 关键词 / 物品 / 语法高亮视觉
**现状**：语法高亮（角色卡/世界书/词条名）已在 `MarkdownViewer` 正文段落生效；关键词触发注入已在后端 prompt 装配层存在；但**前端视觉特效（弹出/飞入/发光）与"每章完成后辨识重叠汉字并标注"完全未做**。
**方向（按你的精确要求）**：
1. **语法高亮范围收窄**：只针对 3 种卡（角色/世界书/词条），每章开头默默开启（现状已是渲染时生效，可改为首屏即开、不展示提示），**不统计出现次数**。
2. **关键词内置效果**：正文出现已注册关键词时，在该词旁给轻量高亮/微光（已有着色基础，补视觉强调），不弹重框。
3. **物品获取效果**：检测到关键细节物品 → 小框从出现位置**飞向背包栏 + 发光**（游戏页 `GameCanvas` 已有 `newEntityFlash`，扩展为"飞入背包"动画）；音效轻、快。
4. **每章完成后辨识重叠汉字**：章节完成后对正文做**完全重叠汉字**（叠字/重复字）扫描并标注 —— 这是新逻辑，需明确：是"连续重复字（如'茫茫'）"还是"同一汉字在章内多次出现"？**待你澄清**（见 K/澄清项）。

## 五、首页船只巡游间距强化（D）

**现状**：v0.46.61 已实现椭圆轨道（`orbitR=3.4+(i%4)*1.15`）+ boids 分离（`separate()` MIN=2.6）。你觉得"还没优化完全"。
**方向**：
1. 把船按**内圈→外圈分层排布**（按字数/层级给不同 `orbitR` 档位），保证内到外明显隔开。
2. 加大最小间距阈值（MIN 2.6 → 更大，如 3.5–4.5），并让各船 `orbitPhase` 错开，避免同相位靠近。
3. 相机/船速微调，确保"绕圈行走、不离太远、绝不穿模"。
