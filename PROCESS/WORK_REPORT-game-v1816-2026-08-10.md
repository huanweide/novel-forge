# 工作单元报告：novel-forge v1.8.16 游戏模式三模式视觉 + 物品跟踪 + 故事线修复

> 面向零基础大一新生的费曼式总结。每个术语第一次出现都用大白话讲清「它怎么运作」，再配一个生活化类比。

## 一、干了什么（一句话）

给小说写作平台 novel-forge 的「游戏模式」做了三件事：① 加了三套可一键切换的视觉风格（黑夜 / 苍青 / 白昼）；② 让游戏里获得物品时屏幕有高亮、有声音、自动归类；③ 修好了「故事线工作台」里主线和支线乱成一团的问题。

## 二、为什么这么做（拆到底层原理）

瑞宝宝（用户）要的是「游戏模式」不只是能跑，还要有氛围感、好用、逻辑清楚。

- **视觉风格**：写小说的人长时间盯屏，单一暗色会腻。三套风格相当于给房间换了三套灯光——同一间屋子，暖光 / 冷光 / 日光，按心情切。关键是：这套灯光**只照亮游戏这块区域**，不能把旁边写正文的「工作区」也染色（那会干扰写作）。
- **物品跟踪**：游戏里捡到宝物，读者（作者）得立刻知道「哟，多了个东西」，就像玩游戏时背包弹出金光提示。否则物品静默入库，作者根本没感知。
- **故事线修复**：之前主线、支线、废弃线全挤在一起，像文件夹里所有文件平铺不分目录。修完变成「一个 main 文件夹 → 里面若干支线子文件夹 → 废弃的单独扔回收站」，符合人脑的分类直觉。

## 三、用了什么方法 / 工具，效果如何

### 关键技术 1：作用域隔离换肤（最核心的一招）

**大白话**：给游戏区域的根 `<div>` 贴一张「风格标签」`<div data-game-theme="night">`，然后在 CSS 里写「凡是贴了 night 标签的树下，辉光色就用紫色」。这样换风格只改这个标签，游戏子树以外的组件一行都不用动。

**类比**：就像给一个房间单独装了智能灯带，你用墙上的开关只控制这个房间，绝不会影响隔壁卧室的灯。

**具体做法**：
- `globals.css` 末尾追加三段：`[data-game-theme="night"]`、`[data-game-theme="twilight"]`、`[data-game-theme="day"]`，每段定义一组 CSS 变量（`--game-glow` 辉光色、`--game-particle` 粒子色等）。day 模式还把整套背景令牌整体覆盖成浅色。
- 切换器是 header 上的三个图标按钮（月亮 / 云 / 太阳），点击后写 `localStorage` 记住选择，下次进来还是这套。

**效果**：零改组件代码完成换肤，工作区主题完全不受影响。tsc 0 错、399 测试全绿验证无回归。

### 关键技术 2：粒子、光影、指针跟随（三种「氛围设计师」）

- **粒子场景设计师**（`GameParticles.tsx` 重写）：屏幕上有 40 个漂浮的光点，每个按 8–15 秒的周期像呼吸一样明暗变化；鼠标靠近时点会被「吸」过来聚成一团，移开又散开。还给了两个开关：降噪（点变少变暗，适合专注）、停动（冻结画面，截图或省电用）。
  - *类比*：像水族箱里的水母，缓慢飘、你手一伸过去它们就围过来。
- **光影艺术设计师**（`globals.css` 的 `.nv-glow` / `.nv-glow-strong` / `.nv-text-glow`）：用多层 `box-shadow`（盒子外发光）和 `text-shadow`（文字外发光）做出霓虹灯效果；重要按钮（开始 / 发送 / 结束导出）默认就发光，鼠标悬停时光晕扩散、按下去光晕收拢下沉，过渡 150–220 毫秒，顺滑不突兀。
- **指针跟随设计师**（`PointerGlow.tsx` 新建）：一张卡片，鼠标移上去时一团冷色光斑用 `transform` 跟随鼠标。
  - *为什么用 transform*：`transform` 只让浏览器做「位移」，不重新计算布局（不重排），所以哪怕快速移动也不卡。类比：搬家具时只平移位置、不重新量房本，所以快。
  - 光斑位置用 `requestAnimationFrame` + 线性插值（每帧只走目标方向的 18%），所以不是硬切、是丝滑追着鼠标。

### 关键技术 3：物品检测（C 任务）

**大白话**：每次 AI 推进剧情生成新物品，系统对比「前后物品清单」，找出新增的那几个，然后：高亮闪一下 + 播一声「叮」+ 从屏幕左侧飞到右侧背包的动画 + 自动跳到背包页。

- 检测是纯前端比对：`name（名字）+ owner（归属谁）` 二元组，新增就标记。声音用 WebAudio 现合成（740→1180Hz 滑音），失败静默不报错。
- 背包分两类：「全部物品」和「角色物品」（角色物品 = 归属不是主角的那些），点上面的分段按钮切换。
- 正文里出现「交易 / 购买 / 出售 / 金币 / 集市」等词，自动在角落弹「交易·<关键词>」小徽章，提醒作者这里发生过买卖。

### 关键技术 4：故事线修复（B 任务）

- **自动排序**：主线按 `order` 字段升序；主线下的支线按「是否完结 + order」排，完结的沉到底部。
- **主线可收起**：每条主线标题旁加展开 / 收起箭头，收起后只显示「主线名 (N)」，N 是支线数，长列表滚动不卡。
- **独立支线并列**：没有归属任何主线的支线，不再硬塞进某条主线，而是单独以「独立支线」分组标签和主线并列。
- **清理废弃线**：头部出现「清理废弃(N)」按钮，点一下弹确认框，确认后批量删除所有标记 `abandoned` 的线。
- **图标语义修正**：支线图标从「箭头」改成「分支」（gitBranch），更像「从主线分出去一条线」的意思。

## 四、关键取舍（工具 A 为何不选 B、踩坑与修复）

1. **换肤用 `data-*` 作用域，不用全局 class 切换**
   - 否决方案：直接改 `<body>` 的 theme class。那样会连工作区一起染色，违背「不影响写作区」的硬要求。
   - 选定方案：`data-game-theme` 只挂在游戏子树，CSS 变量作用域天然隔离。零组件改动是最大收益。

2. **物品辉光色用常量映射，不用 `getComputedStyle` 读变量**
   - 踩坑：最初想从 `document.documentElement` 读 `--game-glow`，但变量定义在 `data-game-theme` 子树里，根节点读不到，会得到空值。
   - 修复：直接写 `GLOW = {night:"167,139,250", twilight:"45,212,191", day:"99,102,241"}` 常量，按当前 `gameTheme` 取色，并把 `gameTheme` 加进 `flagNewItems` 的依赖数组，确保换主题后新物品颜色也跟着变。

3. **排序助手当「函数」用，不当时「比较器」用**
   - 踩坑：`sortChildrenByStatusThenOrder` 是「接收数组、返回排好序的数组」的助手，被误写成 `[...].sort(sortChildrenByStatusThenOrder)`，TS 报类型不匹配。
   - 修复：改成 `sortChildrenByStatusThenOrder([...orphanSides])` 直接返回排序数组，再 `.map` 渲染。

4. **两个弹窗用 Fragment 包起来**
   - 踩坑：`StorylineWorkbench` 的 `return` 里直接放了清理确认弹窗 + 另一个 Modal 两个兄弟节点，JSX 不允许 return 多个根节点，报 `TS1005` / `TS1128`。
   - 修复：用 `<>...</>` 把两个 Modal 包成单一根。

5. **动画全量尊重「减少动态效果」系统设置**
   - 在 `globals.css` 末尾加了 `@media (prefers-reduced-motion: reduce)`，用户系统若开了「减少动画」，所有新增动效（粒子、辉光呼吸、光斑跟随）全部关闭。这是无障碍底线，不省略。
