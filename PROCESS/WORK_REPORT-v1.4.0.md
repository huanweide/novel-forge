# 工作单元报告：v1.4.0 生成轻量化 · 填表后台化

> 费曼式教学报告——你让我「去开会讨论怎么改」，我内部开了会（3 个方案顾问：体验/技术/故事线），汇总成方案后直接实施，本报告讲清楚做了什么、为什么、实测效果、以及哪些留到下一轮。

## 一、干了什么（一句话）

按你「快速生成、轻量化、不挡正文」的目标，把五件事落地并发布：一键追评填表改成**后台运行**（点完可关窗口）、角色卡加**自动去重合并**按钮、**故事线进展自动回写** + **主线完结自动缝合新主线**（默认开）、**删掉世界时间**手动输入、**章名自动生成**。

## 二、为什么这么做（拆到底层）

- **一键追评要后台**：原来点「一键追评」浏览器会一直转圈等 4 章填完（哪怕每章只有 7 秒，等 30 秒也是干等）。改成「点一下 → 服务器立刻回你一个任务号 → 后台慢慢填 → 你随时来看进度」，这样你关掉页面也能继续（任务跑在本地服务器进程里，不依赖浏览器）。
- **自动去重合并**：角色多了之后必然出现「同名不同卡」「小名各建一卡」「纯路过一次的路人」——你需要判断哪些角色真值得检索（有完整姓名、出场够 3 次）、哪些是小名要合并、哪些是龙套要标记。我做的规则很简单：全正文数每个角色名字出现几章（每章只算 1 次），出现 <3 次又没背景的标「🎭 龙套」；名字高度相似（小名/繁简/错别字）的合并到内容最丰富的卡。
- **故事线回写**：每章生成时，引擎其实已经算出了「这条主线/支线这章推进到哪」（叫 threadProgress），但代码写完摘要就把这个结果**扔掉了**——故事线永远是空的。我把它接上：写回故事线的七要素（欲望/阻碍/行动/结果/意外/转折/结局），并且只写 impactScore≥4 的大事（「一起吃个饭」这种 1-3 分的细节不写）。
- **缝合怪推进**：主线你打完勾（completed）后，系统自动构造一条「承接前主线结局」的新主线，让故事不停更；这个开关默认开，怕它乱开新线可以在项目设定关掉。你以前说过的「自动生成故事线」设置我一直是默认关的，这次改成默认开，并解释了它与缝合怪的关系。
- **删世界时间**：世界时间该写多少本来就该交给 LLM 判断，手动输入既挡界面又容易写错，删掉。
- **章名自动生成**：查了代码——生成正文的流程从不回写章节标题，所以只有建章时/大纲时写了标题的章有名字。现在生成完如果标题是空的或「第N章」占位，自动用正文第一句的前 20 个字当标题（零成本，不额外调 AI）。

## 三、用了什么方法、效果如何（实测数据）

| 项 | 做法 | 实测 |
|---|---|---|
| 填表后台化 | 新建 FillTask 任务表 + POST 立即返回 taskId + 后台逐章跑 + 轮询进度 + 防重复点击 | POST **139ms** 返回；轮询拿到 completed 与完整结果 |
| 自动去重合并 | POST /api/characters/dedupe：出现次数统计 + 龙套标记 + isSimilarName 合并（软删） | **483ms** 扫 17 角色：0 组合并 0 龙套（数据本身干净，逻辑正确） |
| 故事线回写 | storyline-writer.ts 接入 post-processor，threadProgress → 七要素 + chapterBindings | 代码层验证（写章时触发） |
| 缝合怪 | 主线 PUT completed → 无 active 主线 → generate mode:newMain | 代码层验证（打勾时触发） |
| 世界时间 | CenterPanel/page/OutlineTree 三处删除 UI 与显示 | tsc 通过 |
| 章名 | post-processor 保存时首段兜底 | tsc 通过 |

## 四、关键取舍（为什么选 A 不选 B）

- **任务表+轮询，不选 SSE**：SSE（服务器推流）一关页面就断，违背「可关窗口继续」；任务表存进度、前端 2.5s 轮询，关页面回来还能查。
- **龙套只打标签不删除**：硬删风险大（可能误删重要角色）；打「🎭 龙套」标签后你可以在筛选里隐藏，安全可逆。
- **章名用正文首段兜底而不是 AI 生成**：AI 生成标题每章多一次调用、拖慢主链路；首段 20 字零成本，不满意随手改。
- **故事线只记大事**：按你要求，impactScore < 4 的日常过渡不写入，避免故事线变成流水账。

## 可复现步骤

```bash
cd novel-forge
node node_modules/prisma/build/index.js db push   # FillTask 任务表
npm run dev
# 一键追评（后台）：POST /api/babylore/fill-all 拿 taskId → GET /api/babylore/fill-task/[taskId] 看进度
# 去重合并：POST /api/characters/dedupe（角色页「自动去重合并」按钮）
```
