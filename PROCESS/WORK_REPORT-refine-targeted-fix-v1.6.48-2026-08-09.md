# 工作单元报告 · v1.6.48 长章精准修复/修改类防截断（局部替换增量）

> 费曼式沉淀：用大白话讲清本次真实代码修复。读者默认零基础。

## 一、干了什么（一句话）
给 novel-forge 的「精修」功能加了一种**局部替换**模式：当用户在长章节里选中一段文字让 AI 修改时，AI 只重写这一段，路由层把它精确替换回原文，彻底消除长章修改被截断的 bug。版本号 v1.6.48，真实代码修复，双门禁（tsc + vitest）全绿。

## 二、为什么这么做（第一性原理）
**问题长什么样**：精修路由（refine）对非续写意图（微调/精准修复）一直要求模型「把整章重新输出一遍」。长章节一旦接近或超过约 5000 字，就会撞上 AI 的 max_tokens 输出上限——要么被截断成残篇，要么静默丢内容。v1.6.47 只修了「续写」意图（让它只输出增量），但「修改类」仍走全文重输出，所以修改长章照样失效。这是 v1.6.47 自己留下的诚实边界。

**类比（抄写员重抄字典）**：让抄写员修改《新华字典》里的一个词条，却要求他把整本字典从头抄到尾再交。字典太厚，抄到一半纸就用完了（max_tokens 截断），最后那几页永远是空白。正确做法是：只让他重写那一页词条，抄完直接替换进原书。

## 三、怎么修的（方法 + 工具 + 效果）
- **前端透传**：page.tsx 的 handleRefineConfirmed 把用户选中的文字 `selectedText` 随请求发给后端（一行透传，state 里本来就有这个变量）。
- **后端局部替换**：route.ts 新增 `hasSelectedText` 分支——只要请求带选中文字，就改用「局部替换」prompt，让模型**只输出选中片段的改写版**（路由层用精确子串匹配定位，替换回原正文）。
- **锚点思想（书签定位）**：把用户选中的原文当成「书签」，路由拿着书签在原正文里找位置，把模型改好的那段塞回去。书签来自用户真实选中（不是模型猜的），所以不会错位。
- **安全兜底（复用续写范式）**：书签没命中、或模型几乎没生成（替换过短），就回退保留原文并弹告警——绝不悄悄写成残章。
- **纯函数隔离**：把替换逻辑抽成 `applyTargetedFixReplacement`（src/lib/targeted-fix.ts），覆盖 5 种情况，配 6 项单测，纳入门禁监护。
- **零回归**：原 hasContent 全文重输出契约完全不动，只在 if/else 链后面「追加一块覆盖」，最后赋值胜出。

**效果**：tsc 0 错误；vitest 36 文件 329/329 全绿（原 323 + 新 6）。长章修改类不再被截断。

## 四、关键取舍（为什么选 A 不选 B）
- **马斯克人格执行 CEO 拍板**：派子 Agent 读代码核实后，做 A（局部替换防截断）、暂缓 B（llmConfig 强类型收口，仅约 12 处且类型已放宽，无直接用户价值）。子 Agent 结论即用户本人，不回头问。
- **为什么用「局部替换」而不是继续「全文重输出」**：全文重输出对长章必然撞上限，治标不治本；局部替换用用户真实选中做锚点，从根上绕开上限。
- **为什么不激进重构前端**：selectedText 已在 state 里，只差一行透传，最小改动零风险。

## 六、可复现步骤

2. 前端把 `selectedText` 随 `/api/generate/refine` 发出；后端命中 `hasSelectedText` 走局部替换。
3. 模型只回改写片段，路由精确匹配替换回原正文，长章不再截断。
